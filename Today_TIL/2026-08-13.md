## 💡 핵심 개념
### 1. 편향(Bias)와 분산(Variance)
**한 줄 정의:**
편향은 모델이 반복적으로 틀리는 정도이고, 분산은 학습 데이터가 바뀔 때 얼마나 흔들리는지를 의미한다.
**쉽게 설명하면:**
- 편향이 높다 → 모델이 너무 단순해서 제대로 못 배움 → 과소적합 → Train, Validation 성능 ↓
- 분산이 높다 → 학습 데이터를 너무 많이 외움 → 과적합 → Train 성능 ↑, Validation  ↓
**나의 궁금증 I : 편향과 분산이 왜 필요할까?** 
- 모델이 왜 성능이 안좋은지 원인을 찾기 위해서
**나의 궁금증 II : 성능이 안좋을 경우 해결 방법**
- 성능이 좋지 않을 때는 먼저 과소적합인지 과적합인지 확인하고 해결방법을 다르게 적용한다.

### 모델 복잡도란: 
모델이 얼마나 복잡한 패턴까지 학습하고 표현할 수 있는지
**쉽게 말해: 모델이 얼마나 세밀하게 문제를 풀 수 있느냐**

### 2. 학습곡선(Learning Curve)
**한 줄 정의:**
훈련 데이터의 양을 바꿔가며 train과 validation 성능을 확인하는 방법
**쉽게 설명하면:**
” 데이터를 더 많이 주면 모델이 더 잘할까? 를 확인하는 방법
validation 성능이 계속 올라가고 있다면 대표적인 데이터를 더 모을 가치가 있을 수있다.
반대로 평평하다면 단순히 데이터만 추가하기보다 특성이나 모델 등을 살펴봐야한다.
**나의 궁금증 I : 갭의 차이가 줄어듬으로서 장단점?**
캡(Train 성능 - Validation 성능)이 줄어드는 것 자체는 보통 좋은 신호
장점: Train에만 잘 맞는 과적합이 줄어들고, 새로운 데이터에서도 더 안정적으로 예측할 가능성이 커짐
단점: 갭이 줄었다고 무조건 좋은 모델은 아님
핵심: 
데이터가 늘면서 Train 과 Validation 의 갭이 줄어드는지 확인
갭이 줄어듦: 과적합이 완화디고 일반화가 좋아질 가능성
단, 갭이 작아도 Train·Validation 성능이 둘 다 낮으면 과소적합일 수 있음

### 3. 검증곡선(Validation Curve)
**한 줄 정의:**
하이퍼파라미터 하나를 바꿔가며 모델의 validation 성능을 비교하는 방
**쉽게 설명하면:**
” 모델을 얼마나 복잡하게 만드는게 좋을까? 를 확인하는 방법
예를 들어 결정트리의 max_depth를 바꿔가며 성능을 비교한다.
**나의 궁금증:
검증곡선에서 가장 이상적인** 
max_depth: 얼마나 깊게 가지를 나눌 수 있는지 제한하는 값
`max_depth ↑`
max_depth ↑
↓
모델 복잡도 ↑
↓
처음에는 Train ↑ + Validation ↑
↓
너무 복잡해지면
↓
Train ↑ + Validation ↓ + Gap ↑
↓
과적합 가능성 ↑

`max_depth ↓`
max_depth ↓
↓
모델 복잡도 ↓
↓
Train 성능 ↓
↓
처음에는 과적합이 줄어 Validation 성능 ↑ 가능
↓
너무 단순해지면
↓
Train 성능 ↓ + Validation 성능 ↓
↓
과소적합 가능성 ↑
> (Notion 이미지: 이상적인_검증곡선_예시_(1).png)
핵심: 검증곡선에서는 Train 성능이 가장 높은 지점이 아니라 Validation 성능이 가장 좋은 지점을 찾는게 중요
예시 그래프에선 max_depth = 5가 가장 이상적이다.
### 4. 규제(Regularization)
**한 줄 정의:**
모델의 계수가 너무 커지지 않도록 벌점(Penalty)를 추가하여 과적합을 줄이는 방법
**쉽게 설명하면:**
모델이 학습 데이터를 너무 많이 외우려고 할 때 브레이크를 거는 것이라고 생각하면 됨
“예측오차 + 계수 벌점” 을 최소화하도록 학습해서 모델이 데이터의 작은 잡음에 너무 민감해지는 것을 줄임.
- 예측오차 → 실제값과 예측값이 얼마나 다른가
- 계수 벌점 → 모델의 계수(가중치)가 너무 커지는 것을 막는 것
- 즉, 모델이 데이터를 잘 맞추면서도 너무 복잡해지지 않도록 하는 것
### 5. Ridge / Lasso / ElasticNet
**한 줄 정의:**
Ridge는 L2, Lasso는 L1, ElasticNet은 L1 + L2 규제를 사용하는 모델이다. 
**쉽게 설명하면:**
Ridge → 계수를 전체적으로 조금씩 줄임 (여러 특성을 함께 유지하고 싶을 때)
Lasso → 일부 계수를 0으로 만듦(필요하지 않은 특성을 줄이거나 선택하고 싶을 때) 
ElasticNet → Ridge + Lasso (특성 선택도 하고 싶고, 비슷한 특성도 함께 유지하고 싶을 때)

## ❓왜 필요한가?
- Train 성능만 높다고 좋은 모델이 아니기때문
- 새로운 데이터에서도 잘하는 일반화 성능이 중요하기 때문
- 과적합이 발생했을 때 모델의 복잡도를 조절하기 위해
- 규제를 이용해 모델이 학습 데이터의 잡음까지 외우는 것을 줄이기 위해
- Ridge, Lasso, ElasticNet 중 문제에 맞는 규제 방법을 선택하기 위해
## ‣ 용어 정리
- 편향(Bias): 모델이 반복적으로 틀리는 정도
- 분산(Variance): 학습 데이터가 바뀔 때 얼마나 흔들리는 정도
- 과소적합(Underfitting): 너무 단순해서 중요한 패턴을 못 배운 상태
- 과적합(Overfitting): 학습 데이터를 너무 많이 외운 상태
- Learning Curve: 데이터 양을 바꿔보는 그래프
- Validation Curve: 하이퍼파라미터를 바꿔보는 그래프
- Regularization(규제): 모델에 브레이크를 거는 방법
- Ridge: L2 규제, Lasso: L1 규제, ElasticNet: L1 + L2의 비율
- alpha: 규제의 전체적인 강도
- l1_ratio: 규제의 전체적인 강도
- coefficient(계수): 각 특성이 예측에 얼마나 영향을 주는지 나타내는 값
## 🧠 내가 이해한 내용
max_depth가 커지면 모델이 복잡해져서 Train 성능이 올라가지만, 너무 커지면 Validation 성능이 떨어지고 Gap이 너무 커져 과적합이 될 수 있다.
반대로 너무 작으면 모델이 지나치게 단순해서 Train과 Validation 성능이 낮아지는 과소적합이 될 수 있다.
## ❓ 헷갈렸던 부분
- Gap이 작다고 무조건 좋은 것은 아니다
- 둘 다 낮으면 과소적합 가능성이 있고
- 둘 다 높으면 좋은 모델 후보이다.
- Gap이 크다고 무조건 과적합도 아니다. Train은 높고 Validation은 낮은지 함께 봐야한다
- max_depth은 모델 복잡도를 조절하는 값이다.
