# 2026-09-04(Transformer 전체 구조)

## 1. 오늘의 학습 목표
- Transformer가 Self-Attention 하나가 아니라 여러 구성요소를 연결한 전체 아키텍처임을 이해한다.
- Token Embedding에 위치 정보를 추가하는 이유와 대표 방식을 설명한다.
- Encoder와 Decoder-only Block의 구조적 차이를 이해한다.
- Attention, FFN, Residual Connection, LayerNorm의 역할을 구분한다.
- Padding Mask와 Causal Mask의 목적을 구분한다.
- Transformer의 주요 Tensor Shape을 `[B, L, D]`, `[B, H, L, L]`, `[B, L, V]` 형태로 추적한다. 
- 긴 Sequence에서 Attention Memory가 증가하는 이유와 Cache의 역할을 이해한다.

## 2. 오늘 배운 내용
### 2-1. Transformer 전체 구조
- 정의: Transformer는 Token Embedding, Position 정보, Attention, FFN, Residual Connection, Normalization, Output Head를 연결한 Attention 기반 신경망 아키텍처이다.
- 왜 필요한가: RNN/ LSTM처럼 정보를 한 시점씩 전달하지 않고, Attention을 이용해 멀리 떨어진 Token끼리 직접 정보를 교환할 수 있다.
- 어떤 목적을 가지는가? : 입력 Token을 문맥이 반영된 표현으로 바꾸고, 그 표현을 분류 및 생성 등 원하는 Task의 출력으로 변환하는 것이 목적이다. 
- 핵심 원리: 
```Plain Text
Token IDs
   ↓
Token Embedding + Position
   ↓
Transformer Block × N
   ↓
Hidden State
   ↓
Task Head
   ↓
Logits
```
### 2-2. Encoder-only / Decoder-only / Encoder-Decoder
- 정의: Transformer의 Encoder와 Decoder를 Task에 따라 다르게 사용하는 구조이다.
- 왜 필요한가: 입력을 이해하는 문제와 새로운 Sequence를 생성하는 문제는 필요한 정보 접근 방식이 다르기 때문이다.
- 어떤 목적을 가지는가?: 
```Plain Text
Encoder-only
→ 입력 전체를 이해하는 것이 목적

Decoder-only
→ 이전 Token을 이용해 다음 Token을 생성하는 것이 목적

Encoder-Decoder
→ 입력 Sequence를 이해하고
   새로운 출력 Sequence로 변환하는 것이 목적
```

### 2-3. Position 정보
- 정의: Token이 Sequence 안에서 몇 번째 위치에 있는지 알려주는 정보이다.
- 왜 필요한가: Self-Attention만으로는 Token의 순서를 명시적으로 알 수 없기 때문이다.
- 어떤 목적을 가지는가: 같은 Token들이 존재하더라도 순서에 따라 다른 문맥을 만들 수 있도록 하는 것이다. 
```Plain Text
Token Embedding
→ 무슨 Token인가?

Position
→ 어디에 있는 Token인가?
```
대표 방법:
```Plain Text
Learned Position Embedding
→ 위치 Vector 자체를 학습

Sinusoidal Encoding
→ sin/cos 규칙으로 위치 정보 생성

RoPE
→ Q와 K를 위치에 따라 회전

결합 후에도:


[B,L,D]


Shape은 유지된다.
```
### 2-4. Encoder Block
- 정의: Self-Attention과 FNN을 중심으로 구성된 Transformer의 기본 Block이다.
- 왜 필요한가: Token끼리 문맥 정보를 교환하고 각 Token의 표현을 다시 가공하기 위해 필요하다.
- 어떤 목적을 가지는가?: 
```Plain Text
Self-Attention
→ Token끼리 정보를 주고받음

FNN
→ 받은 정보를 Token 내부에서 가공

Residual / Norm
→ 이 과정을 깊게 반복해도 안정적으로 학습
```
즉 Encoder Block의 목적은 **각 Token을 주변 문맥이 충분히 반영된 표현으로  만드는 것**이다.
```Plain Text
[B,L,D]
 ↓
Attention
 ↓
Residual + Norm
 ↓
FFN
 ↓
Residual + Norm
 ↓
[B,L,D]
```
### 2-5. Decoder-only와 Causal Mask
- 정의: 미래 Token을 보지 못하게 제한한 Self-Attention을 사용하는 생성 중심 구조이다.
- 왜 필요한가: 다음 Token을 예측하는 모델이 미래 정답을 미리 참고하면 올바른 학습이 불가능하기 때문이다.
- 어떤 목적을 가지는가?: **현재까지 주어진 Token만 이용해 다음 Token을 예측하도록 강제**하는 것이다. 
```Plain Text
Query 0 → 0
Query 1 → 0,1
Query 2 → 0,1,2
Query 3 → 0,1,2,3
```
따라서:
```Plain Text
현재 + 과거 → 사용 가능
미래 → 차단
```
### 2-6. Padding Mask와 Causal Mask
- 정의: Attention에서 참고하면 안 되는 위치를 제한하는 장치이다.
- 왜 필요한가: [PAD]나 미래 정답처럼 모델이 참고하면 안 되는 정보가 존재하기 때문이다.
- 어떤 목적을 가지는가?:
```Plain Text
Padding Mask
→ 존재하지 않는 PAD Token을 정보 계산해서 제외

Causal Mask
→ 미래 Token을 미리 보는 것을 차단
```

```Plain Text
Causal Mask
→ 미래 정보 차단

Label Shift
→ 다음 Token 정답 위치 정렬

labels = -100
→ 특정 위치의 Loss 계산 제외
```
### 2-7. Position-wise FFN
- 정의: 각 Token 위치에 같은 MLP를 독립적으로 적용하는 부분이다.
- 왜 필요한가: Attention으로 받은 정보를 그대로 두지 않고 더 복잡한  Feature 표현으로 가공하기 위해 필요하다
- 어떤 목적을 가지는가?: 각 Token 내부의 Feature을 확장하고 비선형 변환하여 표현력을 높이는 것이다.
```Plain Text
[B,L,D]
 ↓
Linear

[B,L,D_ff]
 ↓
Activation
 ↓
Linear

[B,L,D]

중요한 구분: 
Attention
→ Token과 Token 사이 정보 교환

FFN
→ 한 Token 내부 Feature 가공

```
### 2-8. Residual Connection
- 정의: Y + Sublayer(X) 처럼 원래 입력을 Sublayer의 결과에 다시 더하는 구조이다. 
- 왜 필요한가: Transformer Block을 깊게 쌓아도 정보와 Gradient가 안정적으로 전달되도록 돕기 때문이다.
- 어떤 목적을 가지는가?: 
- 기존 정보를 보존한다.
- Sublayer가 필요한 변화만 학습하게 한다.
- Gradient가 직접 전달될 수 있는 경로를 제공한다. 
```Plain Text
기존 정보 + 새롭게 학습한 변화 = 새로운 표현 
```
### 2-9. LayerNorm / RMSNorm
- 정의: Transformer의 Hidden Feature 크기를 정규화하는 부분이다.
- 왜 필요한가: 여러 Block을 거치며 값의 Scale이 불안정해지는 것을 줄이고 학습을 안정화하기 위해 필요하다
- 어떤 목적을 가지는가: 각 Layer가 다루는 hidden 값의 크기를 안정적으로 관리하여 깊은 Transformer가 학습되기 쉽게 만드는 것이다. 
LayerNorm:
```Plain Text
입력
[B,L,D]

정규화 기준
→ 마지막 D축
```
Pre-Norm:
```Plain Text
Norm
→ Sublayer
→ Residual
```
Post-Norm:
```Plain Text
Sublayer
→ Residual
→ Norm
```
RMSNorm은 최근 Decoder-only LLM에서 자주 사용되는 정규화 방식이다. 
### 2-10. SwiGLU
- 정의: Gate를 사용하는 FNN 구조 중 하나이다.
- 왜 필요한가: 일반적인 FNN보다 Feature 흐름을 더 유연하게 조절하기 위해 사용된다. 
- 어떤 목적을 가지는가: 어떤 Feature를 얼마나 통과시킬지 Gate를 통해 조절하면서 Token 표현을 가공하는 것이다. 
### 2-11. Transformer Shape 추적
- 정의: Transformer 안에서 Tensor가 어떤 정보를 표현하고 있는지 Shape으로 추척하는 것이다
- 왜 필요한가: Transformer 오류의 상당수가 Shape과 축의 의미를 잘못 이해해서 발생하기 때문이다.
- 어떤 목적을 가지는가: 현재 Tensor가 Token ID인지, Hidden Representation인지, Attention Score인지, 최종 Logits인지 정확하게 구분하는 것이다. 
```Plain Text
Raw Text
 ↓
input_ids
[B,L]

 ↓ Embedding

hidden
[B,L,D]

 ↓ Attention 내부

score
[B,H,L,L]

 ↓ Transformer

hidden
[B,L,D]

 ↓ Head

logits
```
Task별 Logits:
```Plain Text
문장 분류
[B,C]

Token 분류
[B,L,C]

Causal LM
[B,L,V]
```
### 2-12. Hidden State와 Logits
- 정의:
Hidden State
→  Transformer 내부 표현
Logits
→ Task의 최종 점수 
- 왜 필요한가: Base Model의 출력과 실제 분류 및 생성 Model의 출력을 구분해야 하기 때문이다.
- 어떤 목적을 가지는가:
```Plain Text
Hidden State
→ 문맥 정보를 저장하고 다음 Layer나 Head로 전달

Logits
→ 실제 Task의 후보별 점수를 표현

Causal LM:

[B,L,D]
 ↓
LM Head
 ↓
[B,L,V]

여기서:
D = 모델 내부 표현 차원
V = Vocabulary 전체 Token 후보 
```
### 2-13. Attention의  **L² 비용**
- 정의: Self-Attention에서는 L개의 Query가 L개의 Key와 관계를 계산한다.
- 왜 필요한가: 긴 Context에서 Transformer의 연산량과 Memory가 빠르게 증가하는 원인을 이해하기 위해 중요하다.
- 어떤 목적을 가지는가: 모델 설계나 학습에서 Sequence Length를 늘리는 것이 어느 정도의 계산 비용을 만드는지 판단하기 위한 기준이 된다. 
```Plain Text
Query = L개
Key   = L개

L × L
=
L²

대표 shape:
[B, H, L, L]
```
L이 2배가 돠면 Score 원소 수는 약 4배가 된다. 
### 2-14. 학습과 생성
- 정의: Causal LM은 학습과 실제 생성에서 Token을 처리하는 방식이 다르다
- 왜 필요한가: Transformer가 병렬 계산이 가능하다고 하면서도 생성 속도에는 한계가 있는 이유를 설명하기 위해 필요하다. 
- 어떤 목적을 가지는가:
```Plain Text
학습 
→ 많은 위치의 다음 Token 예측을 한꺼번에 계산

생성
→ 실제로 다음 Token을 하나씩 결정

학습:
전체 정답 Sequence 존재
→ Causal Mask 사용
→ 여러 위치 병렬 계산

생성:
Token 1 생성 → Token 2 생성 → Token 3 생성 
```
즉 학습 효율과 실제 생성 방식은 서로 다른 문제다. 
### 2-15. Prefill과 Decode
- 정의: LMM 추론을 Prompt 처리 단계와 Token 생성 단계로 나눈 것이다. 
- 어떤 목적을 가지는가:
```Plain Text
Prefill
→ 사용자가 입력한 prompt 전체를 이해하고 초기 K/V를 계산

Decode
→ 저장된 Context를 이용해 다음 Token를 하나씩 생성

Prompt → Prefill → 첫 Token → Decode → 다음 Token → Decode
```
### 2-16. KV Cache
- 정의: 이전 Token에서 계산한 Key와 Value를 Layer별로 저장해 재사용하는 추론용 Cache이다.
- 왜 필요한가: Token을 하나 생성할 때마다 이전 Token의 K/V를 전부 다시 계산하는 비용을 줄이기 위해 필요하다.
- 어떤 목적을 가지는가: Autoregressive 생성에서 이미 계산한 과거 K와 V를 재사용하여 Decode를 빠르게 만드는 것이다. 
```Python
K Cache
[B,H_kv,L_cache,D_head]

V Cache
[B,H_kv,L_cache,D_head]

새 Token이 생기면 L_cache 방향으로 계속 추가된다. 

KV Cache:
과거 K, 과거 V를 저장하고
Model Weight, Attention Score 전체, 확률 전체는 저장하지 않는다. 
```
### 2-17. GQA/ MQA
- 정의: Query Head보다 적은 수의 Key/Value Head를 사용하는 Attention 방식이다
- 왜 필요한가: KV Cache가 긴 Context와 큰 Batch에서 많은 Memory를 사용하기 때문
- 어떤 목적을 가지는가:
```Plain Text
KV Head 수 감소
 ↓
KV Cache 감소
 ↓
추론 Memory 부담 감소

즉, GQA/MQA는 특히 LLM 추론 효율을 연결해서 이해하면 된다. 
```
### 2-18. LLM 추론 지표
- 정의: LLM 서비스의 생성 속도를 서로 다른 관점에서 측정하는 지표이다. 
- 어떤 목적을 가지는가:

```Plain Text
TTFT
→ Prefill 성능

TPOT
→ Decode 성능

Throughput
→ 전체 Serving 처리 능력
```
### 3. 핵심 코드 
Position 정보 추가
```Python
""" 
input_ids에 들어있는 각 Token ID를 학습 가능한 의미 벡터(Embedding Vector)로 변환
input_ids shape: [B, T]
token_hidden shape: [B, T, C]
B = Batch size
T = Sequence Length
C = Embedding Dimension
""" 
# Token의 의미 Vector
token_hidden = token_embedding(input_ids)

"""
각 Token이 문장의 몇 번째 위치에 있는지를 학습 가능한 위치 벡터로 변환
Position_ids 예: [0, 1, 2, 3, ...]
position_ids shape: [B, T] 또는 [T]
position_hidden shape: [B, T, C] 또는 broadcasting 가능한 형태 
"""
# Token의 위치 Vector
position_hidden = position_embedding(position_ids)

"""
Token의 의미 정보와 위치 정보를 같은 위치끼리 더해서 Transformer의 최종 입력을 만든다.
token_hidden : [B, T, C]
position_hidden : [B, T, C]
결과: transformer_input : [B, T, C]
"""
# 의미 + 위치 
transformer_input = token_hidden + position_hidden

목적:

무슨 Token인가? + 어디에 있는 Token인가?
```
두 정보를 Transformer에 함께 전달한다. 
Causal Mask
```Python
"""
L x L 크기의 True 행렬을 만든다.
L = Sequence Length (토큰 개수)
dtype-torch.bool
→ 값의 자료형을 True / False로 설정
"""
causal_mask = torch.triu(
		torch.ones(
				L,
				L,
				dtype=torch.bool
		),
		# diagonal=1 → 주대각선 바로 위부터 위쪽 영역만 남긴다.
		# 즉, 현재 토큰 기준으로 "미래에 있는 토큰 위치만" True가 된다. 
		diagonal=1
)

목적:

현재 / 과거 → 참고가능
미래 → 참고 불가 

다음 Token 예측에서 정답 누출을 막는다. 
torch.triu(..., diagonal=1): 현재 위치보다 뒤에 있는 미래 토큰 위치를 True로 표시하는 
Causal Mask를 만드는 코드
```
FFN + Residual + LayerNorm
```Python
# 입력x의 마지막 차원 D를 기준으로 정규화
# x shape : [B, L, D] 
# B: Batch size
# L:: Sequence Length
# D: Embedding Dimension
norm = nn.LayerNorm(D)

# 각 토큰을 독립적으로 처리하는 작은 신경망
# D → D_FF → D
# 보통 중간 차원 D_FF를 D보다 크게 잡아서 더 다양한 특징을 학습한 뒤 다시 원래 차원D로 줄인다. 
ffn = nn.Sequential(
		
		# 입력 차원 D를 더 큰 차원 D_FF로 확장
		# [B, L, D] → [B, L, D_FF]
		nn.Linear(D, D_FF),
		
		# Transformer에서 자주 사용하는 GELU
		# shape은 그대로 유지
		# [B, L, D_FF]
		nn. GELU(),
		
		# 다시 원래 Embedding 차원 D로 축소
		# [B, L, D_FF] → [B, L, D]
		nn.Linear(D_FF, D)
)
# x를 정규화해서 FFN이 더 안정적으로 학습할 수 있도록 한다.
# shape: [B, L, D] → [B, L, D]
normalized = norm(x)

# 정규화된 입력을 FFN에 넣어서 새로운 특징/변화량을 학습한다.
# shape:[B, L, D] → [B, L, D_FF] → GELU → [B, L, D]
transformed = ffn(normalized)

# 기존 입력 x에 FFN이 새롭게 학습한 transformed를 더한다.
# 기존 정보 + 새롭게 학습한 변화
#       x     : [B, L, D]
# transformed : [B, L, D]
# output      : [B, L, D] 
output = x + transformed

목적: 

Norm
→ 값의 흐름 안정화

FFN
→ Token Feature 가공

Residual
→ 기존 정보와 Gradient 경로 유지
```

### 5. 핵심 정리
Transformer를 공부할 때는 각 기능의 이름만 외우기보다 **이 구성요소가 어떤 문제를 해결하기 위해 존재하는가?** 를 기준으로 이해한다.
```Python
position
→ 순서를 알기 위해

Attention
→ Token끼리 정보를 교환하기 위해

FFN
→ 
Token 표현을 더 풍부하게 가공하기 위해

Residual

Norm
```
