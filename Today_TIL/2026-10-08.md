# 2026-10-08 TIL: 은행 상담 데이터와 분류·생성 프로젝트 설계

## 프로젝트 흐름

상담 내용을 입력받아 문의 유형을 분류하고, 그 분류 결과에 맞춰 생성 모델이 답변을 작성하는 흐름을 이해했다.

text

```
상담 내용 → 분류 모델 → 예측한 문의 유형 → Ollama 생성 모델 → 답변
```

분류 모델은 유형을 고르고, 생성 모델은 문장을 작성한다. 따라서 분류 성능과 답변 품질은 따로 평가해야 한다. 생성 모델에는 데이터에 적힌 정답 라벨이 아니라 분류 모델이 실제로 예측한 라벨을 전달해야 서비스 흐름을 제대로 검증할 수 있다.

## 은행 상담 데이터의 구성

데이터는 학습·검증 용도와 원천·라벨링 형태에 따라 네 파일로 구분된다.

- `TS_은행`: 학습용 원천데이터
- `TL_은행`: 학습용 라벨링데이터
- `VS_은행`: 검증용 원천데이터
- `VL_은행`: 검증용 라벨링데이터

원천데이터에는 상담 내용과 상담 주제 등의 정보가 있다. 라벨링데이터에는 상담 정보와 함께 `qa_data`가 있으며, 그 안의 주요 항목은 다음과 같다.

- `instruction`: 수행할 지시
- `input`: 답변을 만들 때 주어지는 정보
- `output`: 목표 답변

따라서 `TL_은행`과 `VL_은행`은 현재 형태로는 지시형 답변 생성 데이터다. 상담 내용을 입력으로, `consulting_topic` 같은 주제를 정답으로 삼아 가공하면 문의 유형 분류 데이터로도 사용할 수 있다.

## 긴 상담 내용의 처리

`consulting_content`가 너무 길면 모델의 입력 한도와 VRAM에 부담이 될 수 있다. 이때는 긴 상담을 대화 턴 단위로 나누어(chunking) 처리할 수 있다.

다만 상담을 자르는 것만으로 각 조각의 라벨이 자동으로 정해지는 것은 아니다. 전체 상담에 붙은 주제 라벨을 모든 조각에 그대로 복사하면, 해당 조각에는 그 주제의 근거가 없을 수 있다.

분할할 때는 다음 원칙을 지켜야 한다.

1. `TX`·`RX` 발화를 문장 중간이 아닌 대화 턴 기준으로 나눈다.
2. 가능하면 관련된 고객 질문과 상담원 답변을 같은 조각에 둔다.
3. 각 조각에 해당 라벨의 근거가 있는지 확인한다.
4. 분할한 조각에도 원래 상담의 `source_id`를 남긴다.
5. 학습·검증 데이터는 조각이 아닌 `source_id` 기준으로 구분한다.

같은 상담에서 나온 조각이 학습과 검증 양쪽에 들어가면, 모델이 처음 보는 상담을 잘 분류하는 것처럼 평가 결과가 부풀려질 수 있다. 먼저 상담 내용의 실제 길이를 확인하고, 긴 데이터에만 분할을 적용하는 것이 좋다.

## 베이스라인과 모델 비교

베이스라인은 개선 전 성능을 비교하기 위한 기준점이다. 공유된 프로젝트 설계 대화에서는 `TF-IDF + 로지스틱 회귀`를 분류 베이스라인으로 삼고, 사전학습된 분류 모델을 미세조정한 결과와 비교하는 방향이 설명됐다.

비교할 때는 같은 데이터 분할과 평가 지표를 사용해야 한다. 정확도뿐 아니라 Macro-F1과 실제 오분류 사례를 살펴보면 어떤 유형에서 모델이 어려움을 겪는지 이해할 수 있다.

## Ollama와 추가 학습

Ollama에서 사용할 로컬 LLM을 처음부터 사전학습할 필요는 없다. 이미 학습된 모델로 답변 생성을 먼저 시험할 수 있다. 성능 개선을 위해 데이터를 이용해 추가로 학습시키는 것은 미세조정이다. JSON 파일을 Ollama에 넣는 것만으로 모델이 자동 학습되지는 않는다.

## 다음 작업

1. 은행 상담에서 무엇을 분류할지와 사용할 정답 라벨을 정한다.
2. 입력으로 사용할 상담 내용의 길이를 확인한다.
3. 너무 긴 상담만 대화 턴 단위로 나누고, 조각별 라벨을 확인한다.
4. `source_id`가 학습과 검증에 겹치지 않도록 점검한다.
5. 분류 베이스라인을 측정하고 오분류 사례를 기록한다.
6. 분류 모델의 실제 예측 결과를 Ollama 생성 모델에 연결해 답변을 평가한다.

이 내용은 오늘 살펴본 데이터와 공유된 설계 대화를 바탕으로 정리한 것이다. 실제 회의에서 확정한 모델명, 담당 역할, 실험 결과는 아직 확인되지 않아 결정 사항으로 적지 않았다.
