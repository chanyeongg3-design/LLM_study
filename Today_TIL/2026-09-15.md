# TIL — 코드 생성 LLM 비교 실험
**날짜:** 2026-09-15
오늘은 동일한 백엔드 버그 10개를 사용해 `qwen2.5-coder:7b-instruct`와 `deepseek-coder:6.7b-instruct`의 버그 수정 성능을 비교했다. 두 모델 모두 같은 노트북, GPU, 프롬프트, 생성 설정에서 문제별로 2회씩 실행해 총 20회 결과를 기록했다.
결과적으로 Qwen2.5-Coder가 더 좋은 성능을 보였다. 완전 해결 횟수는 Qwen이 6/20회, DeepSeek가 2/20회였고, 생성 속도도 Qwen이 66.2 tokens/s로 DeepSeek의 28.2 tokens/s보다 약 2.3배 빨랐다. 평균 응답 시간은 2.22초와 7.71초, VRAM 점유량은 4,756MiB와 5,943MiB로 Qwen이 더 적게 사용했다.
가장 인상적인 점은 공개 테스트를 통과한 코드가 항상 정답은 아니라는 사실이었다. Qwen은 금액 반올림 문제에서 전체 합계를 한 번만 반올림했고, 평가 테스트에서 항목별 반올림 요구를 충족하지 못해 실패했다. 모델 평가에서는 공개 테스트뿐 아니라 숨겨진 평가 테스트와 구체적인 명세 검토가 함께 필요하다는 점을 배웠다.
DeepSeek에서는 생성 안정성 문제도 확인했다. 한 문제에서는 응답이 중간에 끝나 괄호가 닫히지 않은 `SyntaxError`가 발생했고, 다른 문제에서는 `page_size`를 `pageage_size`로 작성한 단순 오타 때문에 실패했다. 로직 이해도뿐 아니라 코드 생성의 완결성과 세밀함도 모델 선택에 영향을 준다.
다만 이번 결과만으로 모델의 절대적 우위를 단정하기는 어렵다. 문제 수가 10개로 적고, 두 모델의 양자화 방식도 달랐다. 또한 두 모델 모두 멱등성, 재시도, 원자성, Decimal 반올림처럼 상태와 예외 처리가 복잡한 문제에서는 대부분 실패했다.
다음에는 문제 수를 늘리고 양자화 방식을 통일해 재실험할 예정이다. 특히 두 모델이 공통으로 약했던 상태 관리와 예외 처리 문제를 더 세분화해 분석하고 싶다.
**한 줄 정리:** Qwen2.5-Coder가 이번 실험에서는 더 나은 후보였지만, 복잡한 백엔드 로직을 안정적으로 수정하기에는 두 모델 모두 추가 검증이 필요하다.
