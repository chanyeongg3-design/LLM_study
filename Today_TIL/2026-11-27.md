# LLM Fine-tuning 1~8장 통합 

## 1. 학습 목적

Qwen2.5-0.5B-Instruct를 기반으로 합성 출장 규정 도우미를 구축하여 **데이터 준비, 모델 학습, 평가, 후보 선정, 최종 검증, 복원 및 인계**까지 전체 라이프사이클을 이해한다.

### 4-2. LoRA 가중치 업데이트

![[Pasted image 20261127151129.png]]

- W: 기존 모델 가중치
- A: 입력 차원 축소
- B: 출력 자원으로 변환
- r: Rank, 저랭크 행렬의 내부 차원
- α: 어댑터 스케일링 설정
- 최종 출력: y = Wx + (α/r)BAx

**QLoRA는 W를 NF4 4비트로 양자화하고 A·B만 학습한다.**

### 4-4. JSON 설정 해시 생성

```python
def json_sha256(value):
    # 키 순서 및 공백 표준화
    canonical = json.dumps(
        value,
        ensure_ascii=False,
        sort_keys=True,
        separators=(",", ":")
    )

    # UTF-8 바이트 변환 및 해시 생성
    return hashlib.sha256(
        canonical.encode("utf-8")
    ).hexdigest()
```

Dictionary → Canonical JSON → Bytes → SHA-256

키 순서나 들여쓰기가 달라도 데이터의 값이 같으면 동일한 해시를 생성한다. 평가 설정이 변경되었는지 확인하기 위해 사용한다.

## 6. 새롭게 이해한 부분 및 복숩할 내용

- **attetion_mask와 labels=-100**: Attention 참조 제어와 Loss 계산 제외의 차이
- **Loss와 답변 품질**: Loss 또는 DPO Margin 개선이 실제 생성 품질을 보장하지 않는다.
- **Dev와 Test**: 모델 선정과 최종 검증을 분리하여 데이터 누수를 방지한다.
- **형식과 업무 판단**: JSON 형식이 정상이어도 답변 내용은 틀릴 수 있다.
- **조건 동결과 Weight Freeze**: 평가 조건 확정과 모델 가중치 동결은 서로 다르다.
- **Checkpoint와 Handoff Bundle**: 학습 재개용과 추론·인계용의 차이.
- **재현성과 배포 준비**: 모델 복원 성공이 업무 정확성이나 운영 적합성을 보장하지 않는다.

**추가 복습**: LoRa 행렬 연산, DPO Loss 계산, 전체 파인튜닝 직접 구현, 한도 초과 판단 오류 개선.

## 7. 오늘의 한 줄 정리

파인 튜닝은 단순히 모델을 학습시키는 것이 아니라, 적합한 모델을 선정하고 성능과 한계를 검증하여 재현 가능한 근거와 함께 인계하는 과정이다.
