# 1. 오늘은 무엇을 공부했을까?
BM25: 정확한 단어를 기준으로 문서를 검색한다.

Dense Search: 문장의 의미를 기준으로 문서를 검색한다.

Hybrid Search: 서로 다른 검색 방식을 결합한다.

RRF: 여러 검색 결과의 순위를 하나로 합친다.

Re-ranking: 검색된 후보의 순위를 다시 평가한다.

Query Rewrite: 검색에 적합하도록 질문을 재작성한다.

Multi-Query: 하나의 질문을 여러 표현으로 확장하여 검색한다.
오늘은 RAG 시스템에서 **검색한 문서를 바탕으로 신뢰할 수 있는 답변을 생성하고, 검색 성능을 개선하는 방법**을 공부했다.

오전에는 검색 결과를 LLM이 이해할 수 있는 Context로 구성하고, 답변에 출처를 연결하는 과정을 배웠다.

특히 문서가 검색되었다고 해서 반드시 답변할 수 있는 것은 아니라는 점이 중요했다.

오후에는 BM25와 Dense 검색을 비교하고, Hybrid Search, RRF, Re-ranking, Query Rewrite를 통해 검색 정확도를 높이는 방법을 학습했다.

# 2. 최종 핵심 요약 
- Context 구성: 검색한 청크의 중복을 제거하고, 필요한 근거를 LLM에 전달하는 과정
- Citation: 생성한 답변이 실제 문서의 어떤 내용을 근거로 하는지 연결하는 기능
- BM25: 정확한 단어를 기준으로 문서를 검색
- Dense Search: 문장의 의미를 기준으로 문서를 검색한다.
- Re-ranking: 검색된 후보의 순위를 다시 평가한다. 
- Hybrid Search / RRF: 여러 검색 결과를 결합하고 순위를 통합하는 방법
- Re-ranking: 검색된 후보를 질문과의 관련성에 따라 다시 정렬하는 과정
- Query Rewrite: 원래 질문의 의도를 유지하면서 검색에 유리한 표현으로 바꾸는 방법
- Multi-Query: 하나의 질문을 여러 표현으로 확장하여 검색한다. 

- RRF: 여러 검색 결과의 순위를 하나로 합친다.

## 2-1. BM25 - 키워드 기반 검색

**정의**: 질문에 포함된 단어와 문서의 단어가 얼마나 일치하는지 계산하는 검색 방식 

**사용 이유**: 정확한 용어나 특정 키워드가 포함된 문서를 빠르게 찾기 위해 사용한다.

**작동 원리**: 
- 질문을 단어 단위로 분리
- 문서에 해당 단어가 등장하는지 확인
- 단어의 등장 빈도, 희소성, 문서 길이를 고려해 점수를 계산
- 점수가 높은 문서를 우선 반환

## 2-2. Dense Search - 의미 기반 검색

**정의**: 질문과 문서를 임베딩 벡터로 변환하고, 벡터 사이의 유사도를 계산하는 검색 방식이다.
**사용 이유**: 질문과 문서의 표현이 서로 달라도 의미가 비슷한 문서를 찾기 위해 사용한다.
**작동 원리**: 
- 질문을 임베딩 모델에 입력
- 질문을 숫자 벡터로 변환
- 저장된 문서 벡터들과 유사도를 계산
- 유사도가 높은 문서를 반환

## 2-3. Hybrid Search - 검색 방식 결합

**정의**: BM25와 Dense Search 등 여러 검색 방식을 함께 사용하는 전략이다.
**사용 이유**: 한 가지 검색 방식의 단점을 다른 검색 방식으로 보완하기 위해 사용한다.
**작동 원리**:
- BM25로 키워드 기반 검색을 수행한다.
- Dense Search로 의미 기반 검색을 수행한다.
- 두 검색 결과를 수집한다.
- RRF 등의 방법을 사용해 결과를 결합한다.

## 2-4. RRF -  검색 순위 통합
**정식 명칭**: Reciprocal Rank Fusion

**정의**: 여러 검색 방식에서 반환된 결과를 순위에 따라 통합하는 알고리즘이다.
**사용 이유**: BM25와 Dense 유사도 점수는 계산 기준이 다르므로 직접 비교하기 어렵기 때문이다.
**핵심 공식**: RRF 점수 = 각 검색 결과에서 얻은 1 / (k + 순위)의 합
**특징**: 
- 검색 결과의 원래 점수 대신 순위를 사용
- 여러 검색 방식에서 높은 순위에 등장한 문서가 유리
- 검색 결과를 합칠 때 유용

## 2-5. Re-ranking - 검색 결과 재정렬
**정의**: 검색된 후보 문서를질문과 다시 비교하여 관련성이 높은 순서로 정렬하는 과정이다.
**사용 이유**: 최초 검색에서 관련 문서를 찾았더라도 가장 좋은 문서가 1위에 있지 않을 수 있기 때문이다.
**작동 원리**:
- BM25 또는 Dense Search로 후보 문서를 검색한다.
- 질문과 후보 문서를 함께 Re-ranking 모델에 입력한다.
- 모델이 질문과 문서의 관련성을 평가한다.
- 관련성이 높은 문서를 상위에 배치한다.

## 2-6. Query Rewrite - 질문 재작성
**정의**: 사용자의 원래 의도를 유지하면서 검색하기 유리한 문장으로 질문을 변경하는 방법이다.
**사용 이유**: 사용자의 질문이 짧거나 모호할 경우 검색 성능이 떨어질 수 있기 때문이다. 

## 2-7. Multi-Query - 다중 질문 검색
**정의**: 하나의 질문에서 여러 검색어를 만들어 각각 검색하는 방식이다.
**사용 이유**: 문서마다 같은 내용을 다른 표현으로 작성할 수 있기 때문이다.

# 3. 공부하면서 고민했던 부분

오늘은 bind_claim()을 사용하면서 **함수에 전달하는 데이터와 반환하는 값의 차이**가 궁금했다.

특히 status, linked= bind_claim(candidate, lookup)코드를 살펴보며, 함수에 두개의 인자를 전달하고 반환된 결과를 각각의 변수에 저장한다는 점을 이해했다.

오후에는 Query Rewrite 실습 코드를 살펴보면서 LLM이 생성한 검색어를 리스트에 추가하고, 중복을 제거하는 과정을 공부했다.

이 과정에서 단순히 검색어를 많이 만드는 것보다 질문의 원래 의미를 유지하면서 필요한 근거를 찾는 것이 중요하다고 느꼈다. 

# 4. 오늘 느낀 점

이전까지는 RAG에서 관련 문서를 잘 검색하는 것이 가장 중요하다고 생각했다.

하지만 오늘 공부하면서 검색 결과를 어떻게 구성하고, 근거를 어떻게 검증하며, 근거가 부족할 때 어떻게 대응하지도 종요하다는 것을 알게 되었다.

또한 검색 성능이 부족하다면 무조건 LLM 모델을 변경하기보다 BM25, Dense, Re-ranking, Query Rewrite 같은 검색 기술부터 개선할 수 있다는점이 인상 깊었다.

결국 좋은 RAG 시스템은 단순히 답변을 잘 생성하는 시스템이 아니라, 올바른 근거를 찾아 검증하고 신뢰할 수 있는 답변을 제공하는 시스템이라는 것을 배웠다.
