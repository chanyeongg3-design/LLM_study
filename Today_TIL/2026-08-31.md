## 2. CNN — 이미지의 공간 구조를 활용하는 신경망
### 2-1. 왜 이미지에는 CNN을 사용할까?
CIFAR-10 RGB 이미지 한 장은 다음과 같은 구조를 가진다.
```Plain Text
(3, 32, 32)

3 = RGB Channel
32 = Height
32 = Width
```
Batch까지 포함하면:
```Plain Text
(N, C, H, W)
(N, 3, 32, 32)
```
이미지는 서로 가까운 픽셀끼리 관계가 있다는 특징이 있다.
Ex) 눈, 코, 귀, 모서리 같은 특징은 특정 픽셀 하나가 아니라 주변 픽셀의 조합으로 나타난다.
CNN은 이러한 이미지의 **지역성(Locality)을 활용한다.** 
CNN의 기본 흐름:
```Plain Text
이미지
 ↓
Conv2d
 ↓
ReLU
 ↓
MaxPool2d
 ↓
Conv2d
 ↓
ReLU
 ↓
MaxPool2d
 ↓
Flatten
 ↓
Linear
 ↓
Logits
```
각 : Layer의 역할

즉 CNN은 크게 Feature Extraction → Classification 두 단계로 볼 수 있다. 
### 3. Feature Map과 Channel
- CNN에서 매우 중요한 개념이 Feature Map이다.
```Python
예를 들어:
nn.Conv2d(
		in_channels=3,
		out_channels=16,
		kernel_size=3,
		padding=1
)

입력이 (N, 3, 32 ,32) 라면 출력은 (N, 16, 32, 32)가 된다.
```
여기서 16은 클래스 개수가 아니고, 16개의 Filter가 서로 다른 특징을 찾기 때문에 
16개의 Feature Map이 생성된 것이다. 
```Python
쉽게 생각하면:

Filter 1 → 특정 경계 특징
Filter 2 → 다른 방향의 경계
Filter 3 → 색 변화
Filter 4 → 질감
...
처럼 각 Fliter가 다른 패턴을 학습할 수 있다.
따라서 CNN이 깊어지면서 Channel 수를 3 → 16 → 32 → 64 처럼 늘리는 이유는
더 다양한 특징 표현을 학습할 수 있게 하기 위해서다.  
```
### 4. CNN Shape 변화 완전히 이해하기
```Python
self.features = nn.Sequential(
		
		# RGB 이미지에서 16개의 특징을 추출
		nn.Conv2d(3, 16, kernel_size=3, padding=1),
		nn.ReLU(),
		
		# 공간 크기를 절반으로 감소
		nn.MaxPool2d(2),
		
		# 16개의 특징을 이용해 32개의 더 복잡한 특징 생성
		nn.Conv2d(16, 32, kernel_size=3, padding=1),
		nn.ReLU(),
		
		# 다시 공간 크기를 절반으로 감소
		nn.MaxPool2d(2)
)
```
```Python
Input
(N, 3, 32, 32)

        ↓ Conv2d 3 → 16

(N, 16, 32, 32)

        ↓ MaxPool2d(2)

(N, 16, 16, 16)

        ↓ Conv2d 16 → 32

(N, 32, 16, 16)

        ↓ MaxPool2d(2)

(N, 32, 8, 8)

        ↓ Flatten

(N, 2048)
```
Classifier는 
```Python
self.classifier = nn.Linear(
		32 * 8 * 8, # CNN이 추출한 Feature 개수
	  10          # CIFAR-10 Class 개수   
)
```
**⭐ 꼭 구분하기**
```Python
Conv2d out _channels
          ↓
   Feature Map 개수
          ↓
Linear out_features
          ↓
   최종 Class 개수 

```
### 5. CNN 학습 Pipeline
CNN도 결국 일반적인 딥러닝 학습 구조를 그대로 사용한다
```Python
Dataset
↓
DataLoader
↓
Image Batch
↓
CNN
↓
Logits
↓
Loss
↓
Backward
↓
Optimizer

```
```Python
model.train()

for images, labels in train_loader:
		# 모델이 있는 CPU/GPU와 같은 장치로 이동
		images = images.to(device)
		labels = labels.to(device)
		
		# 이전 Batch에서 계산된 Gradient 초기화
		optimizer.zero_grad()
		
		# Forward
		logits = model(images)
		
		# 예측과 정답을 이용해 Loss 계산
		loss = criterion(logits, labels)
		
		# Loss를 기준으로 Gradient 계산
		loss.backward()
		
		# 계산된 Gradient로 Parameter 업데이트 
		optimizer.step()
		
		핵심 흐름:
		zero_grad() -> forward -> loss -> backward() -> step()
```

### 8. CNN과 GPU Memory 
GPU 메모리 저장되는 것
CNN 학습 시 GPU에는 모델 파라미터만 저장되는 것이 아니다.
```Plain Text
GPU Memory
├─ Input Batch              # 입력 이미지
├─ Model Parameters         # 가중치와 편향
├─ Intermediate Activations # 중간 Feature Map
├─ Gradients                # 역전파에서 계산된 기울기
└─ Optimizer State          # Adam 등의 추가 상태값
```
특히 CNN은 여러 합성곱 계층에서 많은 Feature Map을 생성하므로 메모리 사용량이 커질 수 있다. 
Batch Size와 GPU 메모리
```Python
Batch Size 증가
→ 동시에 처리하는 이미지 수 증가
→ 저장해야 하는 Feature Map 증가
→ GPU 메모리 사용량 증가
따라서 CUDA Out Of Memory가 발생하면 가장 먼저 Batch size를 줄여본다. 
```
Validation 메모리 절약
Validation에서는 역전파가 필요 없으므로 torch.no_grad( )를 사용한다
```Python
model.eval()

with torch.no_grad():
		outputs = model(x_valid)
		valid_loss = criterion(outputs, x_valid)

이렇게 하면 불필요한 계산 그래프 생성을 막아 메모리 사용량을 줄일 수 있다. 
```
Logging 시 주의점
```Python
# ❌ Tensor를 저장하여 계산 그래프가 계속 참조될 수 있
loss_history.append(loss)
# ✅ Python 숫자로 변환하여 저장
loss_history.append(loss.item())

# loss.item()은 스칼라 Tensor를 Python 숫자로 변환하기 때문에 계산 그래프를 계속 보관하지 않는다.
```
torch.cuda.empty_cache( )의 한계
`torch.cuda.empty_cache()` : 이 함수는 PyTorch가 캐시해 둔 사용하지 않는 GPU 메모리를 반환한다.
하지만 현재 Tensor가 사용 중인 메모리나 계산 그래프가 참조하고 있는 메모리는 제거하지 못한다.
따라서 empty_cache( )는 근본적인 OOM 해결책이 아니다. 
핵심 정리
> CNN의 GPU 메모리는 Parameter뿐만 아니라 입력, Feature Map, Gradient, Optimizer State가 함께 사용한다.
> OOM이 발생하면 먼저 Batch size를 줄이고, Validation에서는 torch.no_gard(), 기록할 때는 loss.item( )을 사용한다.

### 16. RNN — 이전 정보를 기억하면서 처리하기
RNN의 핵심은 Hidden State다.
일반적인 신경망이:`현재 입력 → 출력` 이라면 RNN은: 
```Plain Text
현재 입력
+
이전 Hidden State
       ↓
새 Hidden State 
를 계산한다.

즉,
x1 → h1
      ↓
x2 → h2
      ↓
x3 → h3
      ↓
x4 → h4
```
h1의 정보가 h2, h3, h4로 전달된다
Hidden state는 쉽게 말해: 
> **지금까지 읽은 내용을 요약해 가지고 다니는 메모장** 이라고 생각하면 된다
### 17. RNN의 output과 h_n
```Plain Text
x = torch.randn(4, 6, 3)

rnn = nn.RNN(
		input_size=3,
		hidden_size=8,
		batch_first=True
)

output, h_n=rnn(x)

shape는
x (4, 6, 3) → output (4, 6, 8), h_n (1, 4, 8)

output: (batch, seq_len, hidden_size)

모든 시점의 Hidden State가 들어 있다.
output[:, 0, :] → 첫 시점
output[:, 1, :] → 두 번째 시점
...
output[:, -1, :] → 마지막 index

h_n ( D x num_layer, batch, hidden_size)
각 Layer와 방향의 최종 Hidden State다
⭐ batch_first=True는 input과 output에 적용되며 h_n의 차원 순서는 바꾸지 않는다. 
```
### 18. Sequence Classification과 마지막 유효 시점
문장 전체를 **긍정 / 부정** 처럼 하나의 class로 분류한다고 생각하자
```Plain Text
기본흐름:
Sequence
↓
RNN
↓
마지막 유효 Hidden State
↓
Linear
↓
Logits
```
padding이 없는 고정 길이 데이터라면:
```Python
output, h_n=self.rnn(x)

# 마지막 시점의 정보를 선택
last_hidden = output[:, -1, :]

# Class 점수 생성
logits =self.fc(last_hidden)
```
최종 shape:
```Plain Text
(batch, seq_len, hidden_size)

↓

(batch, hidden_size)

↓ Linear

(batch, num_classes)
```
### 19. Padding이 있다면?
실제 문장은 길이가 다르다. 
`output[ : , -1, : ]` 를 사용하면 B와 C에는 PAD 위치를 가져오게 된다
따라서 실제 길이를 사용해야 한다. 
```Plain Text
lengths = torch.tensor([6, 4, 2])

# 실제 마지막 Token의 index
last_index = lengths -1 

batch_index = torch.arange(output.size(0))

# 각 Sequence의 마지막 유효 Hidden State 선택 
last_hidden = output[batch_index, last_index]
```
> 따라서: output[ : , -1, : ]은 **고정 길이·무패딩에서다만 안전하다.**
### 20. RNN의 문제 — 장기 의존성
RNN은 이론적으로 과거 정보를 계속 전달할 수있다.
하지만 Sequence가 길어지면 문제가 생길 수있다.
```Plain Text
초반 중요한 정보
↓
h1
↓
h2
↓
h3
↓
...
↓
h100
```
초반 정보가 매우 먼 시점까지 전달되어야 한다.
> 이를 장기 의존성(Long-Term Dependency) 문제와 연결해서 이해할 수 있다. 
### 21. Vanishing / Exploding Gradient
RNN은 역전파할 때 여러 시점을 거슬러 Gradient가 전달된다. 
```Plain Text
Loss
↓
h5
↓
h4
↓
h3
↓
h2
↓
h1
```
작은 값이 반복해서 곱해지면:
```Plain Text
0.5 x 0.5 x 0.5 x 0.5 = 0.0625
```
Gradient가 매우 작아질 수 있다.
Vanishing Gradient
`Gradient → 0`  초반까지 학습 신호가 제대로 전달되지 않는다. 
반대로 큰값이 반복되면: Exploding Gradient 
`Gradient → 매우 큰 값`  학습이 불안정해질 수 있다. 
### 22. Gradient Clipping
Exploding Gradient를 완화하기 위해 사용할 수 있다.
```Plain Text
# Gradient 계산
loss. backward()

# Gradient가 너무 커지는 것을 제한
torch.nn.utils.clip_grad_norm_(
		model.parameters(),
		max_norm=1.0
)

# Parameter 업데이이트
optimizer.step()
```
위치:
```Plain Text
backward()
↓
Gradient Cliping
↓
optimizer.step()
```
중요: 
> Gradient Clipping은 Exploding Gradient를 완화하는 방법이며 Vanishing Gradient 자체를 해결하지 않는다. 
### 23. LSTM — 기얼을 더 잘 관리하는 RNN
RNN의 장기 의존성 문제를 완화하기 위해 LSTM이 등장했다
RNN은 주로:
```Python
Hidden State 를 통해 정보를 전달한다
```
LSTM:
```Python
Hidden State
+
Cell State
+
Gate
를 사용한다
```
### 24. Cell State와 Gate
Cell State는 오래 유지할 기억을 전달하는 경로라고 이해할 수있다.
LSTM의 흐름
```Plain Text
이전 Cell State
       ↓
   Forget Gate
       ↓
남겨둘 이전 기억
       │
       ├──────────┐
       │          │
현재 입력          │
   ↓              │
Candidate         │
   ↓              │
Input Gate        │ㅁ
   ↓              │
새로 저장할 기억 ───┘
       ↓
새 Cell State
       ↓
Output Gate
       ↓
새 Hidden State
```
### 각 역할: 
1. Forget Gate: 기존 기억을 얼마나 남길까?
1. Candidate: 새로 기억할 내용은 무엇일까?
1. Input Gate: 새로운 내용을 얼마나 저장할까?
1. Cell State: 어떤 기억을 오래 유지할까?
1. Output Gate: 지금 어떤 기억을 꺼내 사용할까?
⭐ Candidate는 Gate가 아니다
> Gate는 sigmoid를 이용해 0 ~ 1의 비율을 만들고, Candidate는 tanh를 이용해 새로운 기억 후보를 만든다. 
### 25. LSTM 핵심 계산 
Gate:
```Python
f_t = sigmoid(...) # Forget Gate
i_t = sigmoid(...) # Input Gate
o_t = sigmoid(...) # Output Gate
```
Candidate:
```Python
g_t = tanh(...)
```
Cell State:
```Python
c_t (새 기억)
= 
f_t x c_(t-1) (남겨둘 기존 기억)
+ 
i_t x g_t (저장할 새로운 기억)
```
Hidden State:
```Python
h_t = o_t x tanh(c_t)
```
> 즉, Cell State에 있는 기억 중 **현재 사용할 정보를 꺼내 Hidden State로 만든다**.

### 27. RNN → LSTM → Transform 연결
전체 흐름을 연결해보면:
```Python

↓

↓

↓

↓

↓

↓

↓
```

하지만 LSTM도 여전히: **x1 → x2 → x3 → x4** 순서대로 계산해야 한다.

따라서 Sequence가 길어지면 **시간축 병렬 처리에 제약**이 있다.
또 아주 긴 문맥의 정보 전달도 완벽하게 해결한 것은 아니다.
이러한 한계가 이후 **Attention과 Transformer 같은 다른 Sequence 구조가 발전한 배경**이 된다.

### 31-4. CNN 학습 코드
```Python
def train_one_epoch(
		model,
		train_loaderm
		criterion,
		optimizer,
		device
):
		
		# 학습 모드 
		model.train()
		
		total_loss = 0.0
		correct = 0
		total = 0
		
		for images, labels in train_loader:
				
				# 모델과 데이터를 같은 device로 이동
				images = images.to(device)
				labels = labels.to(device)
				
				# 이전 Batch의 Gradient 초기화
				optimizer.zero_grad()            # optimizer.zero_grad()
				
				# Forward
				# 이미지 -> 모델 -> Logits
				logits = model(images)           # logits = model(x)
				
				# 예측과 정답의 차이를 계산
				loss = criterion(images, labels) # loss = criterion(logits, y)
				
				# Gradient 계산
				loss.backward()                  # loss.backward()
				
				# 파라미터 업데이트 
				optimizer.step()                 # optimizer.step()
				
				# 현재 Batch 크기
				batch_size = images.size(0)
				
				# Epoch 전체 Loss 계산을 위해 누적 
				total_loss += loss.item() * batch_size
				
				# 가장 높은 Logits의 Class 선택
				preds = logits.argmax(dim=1)
				
				# 맞춘 개수 누적
				correct += (preds == labels).sum().item()
				
				# 전체 Sample 수 누적
				total += batch_size
		
		# Epoch 평균 Loss		
		avg_loss = total_loss / total
		
		# Epoch Accuracy
		accuracy = correct / total
		
		return avg_loss, accuracy
```

### 39. LSTM Sequence Classifier
```Python
class LSTMClassifier(nn.Module):
    def __init__(
        self,
        input_size,
        hidden_size,
        num_classes
    ):
        super().__init__()

        # Sequence를 처리하는 LSTM
        self.lstm = nn.LSTM(
            input_size=input_size,
            hidden_size=hidden_size,
            batch_first=True
        )

        # Hidden State를 Class Logits로 변환
        self.fc = nn.Linear(
            hidden_size,
            num_classes
        )

    def forward(self, x):

        # output:
        # 모든 시점의 Hidden State
        #
        # h_n:
        # 마지막 Hidden State
        #
        # c_n:
        # 마지막 Cell State
        output, (h_n, c_n) = self.lstm(x)

        # 고정 길이 + 무패딩 예제이므로
        # 마지막 시점 Hidden State 선택
        last_hidden = output[:, -1, :]

        # Class별 Logits 생성
        logits = self.fc(last_hidden)

        return logits
```
