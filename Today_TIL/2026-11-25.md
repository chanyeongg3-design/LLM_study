# 2. 데이터 무결성과 실험 재현성

## 데이터 무결성(Integrity)
데이터가 기존 비교 기준과 달라지거나 손상되지 않았는지 확인하는 것이다. SHA-256을 활용하여 파일의 동일성을 검증한다.

```python
hashlib.sha256(dev_bytes).hexdigest()
```

| 코드            | 역할                |
| ------------- | ----------------- |
| `hashlib`     | 해시 기능을 제공하는 모듈    |
| `sha256()`    | 256비트 해시값 계산      |
| `hexdigest()` | 64글자의 16진수 문자열 반환 |

## 실험 재현성(Reproducibility)

동일한 조건에서 실험을 다시 수행하고 결과를 비교할 수 있도록 실험 정보를 관리하는 것이다

| 검증 항목         | 목적                       |
| ------------- | ------------------------ |
| `MODEL_ID`    | 동일한 기반 모델 확인             |
| `REVISION`    | 동일한 모델 버전 확인             |
| `data_sha256` | 동일한 학습 데이터 확인            |
| `case_id`     | 동일한 평가 문항 확인             |
| `messages`    | 동일한 시스템 지시사항, 질문 및 근거 확인 |
| `generation`  | 동일한 생성 설정 9개 확인          |
```python
# 현재 데이터와 보고서의 학습 데이터 일치 여부 검증
if (
	reports[name].get("data_sha256")
	!= input_sha256["training_data_zip"]
):
	raise ValueError("학습 데이터가 다릅니다.")
```

**핵심**: 해시값의 일치는 파일의 동일성을 의미하며, 모델의 성능이나 학습 설정의 적절성을 보장하지 않는다.

# 7. Call Chain 및 함수별 입출력

Call Chain은 프로그램 내부의 함수 호출 순서와 함수 간 호출 관계를 나타낸다.

| 함수                        | 입력          | 기능        | 출력         |
| ------------------------- | ----------- | --------- | ---------- |
| `file_sha256`             | 파일 경로       | 해시 계산     | 문자열        |
| `check_dev_records()`     | Dev 데이터, 명세 | 데이터 검증    | None 또는 오류 |
| `check_format_examples()` | 예제 응답       | 검사 기능 테스트 | None 또는 오류 |
| `inspect_response()`      | 응답, 문서 ID   | 형식 검사     | 딕셔너리       |
| `retrieve_document`       | 질문,팀        | 문서 검색     | 리스트        |
| `generate_answer`         | 질문, 문서      | 답변 생성     | 딕셔너리       |
| `answer()`                | API 요청      | 전체 기능 연결  | API 응답     |

## API Call Chain

POST /answer
│
├── AnswerRequest              # 입력 검증
│
└── answer()
    ├── retrieve_documents()  # 문서 검색
    │
    ├── generate_answer()      # 답변 생성
    │   ├── json.dumps()
    │   ├── apply_chat_template()
    │   ├── model.generate()
    │   └── tokenizer.decode()
    │
    ├── inspect_response()     # 응답 검증
    │   ├── json.loads()
    │   ├── isinstance()
    │   └── issubset()
    │
    └── JSONResponse()         # 결과 반환

**함수명 → 매개변수 → 내부 처리 → 반환값 → 다음 함수** 순서로 파악

# 8. 내가 질문하고 배운 문법 및 용어

| 문법 및 함수              | 핵심 의미                      |
| -------------------- | -------------------------- |
| `def 함수명(매개변수)`      | 외부 값을 전달받는 함수 정의           |
| `get()`              | Key에 해당하는 Value 반환         |
| `get(key, {})`       | Key가 없으면 빈 딕셔너리 반환         |
| `set()`              | 집합으로 변환하여 중복 제거            |
| `namelist()`         | ZIP 내부 파일명 목록 반환           |
| `decode("utf-8")`    | 바이트 데이터를 문자열로 변환           |
| `splitlines()`       | 문자열을 줄 단위로 분리              |
| `ensure_ascii=False` | JSON 변환 시 한글 등을 그대로 표현     |
| `assert`             | 조건이 참인지 검증                 |
| `all()`              | 모든 항목이 참인지 확인              |
| `next()`             | 반복자의 다음 항목 반환              |
| `Counter()`          | 항목별 발생 횟수 단계               |
| `issubset()`         | 부분집합 여부 확인                 |
| `role`               | 메시지의 역할                    |
| `row / rows`         | 개별 데이터 / 데이터 목록            |
| `citation`           | 답변 근거의 출처                  |
| `Alignment`          | 모델의 행동을 인간의 의도와 선호에 맞추는 과정 |
### **중요 질문 ①. 빈 딕셔너리의 사용 목적**

```python
reports["dpo"].get("input_sha256", {}).get(name)
```

Key가 존재하지 않을 경우 빈 딕셔너리를 반환하여 뒤의 `.get(name)`호출에서 오류가 발생하는 것을 방지한다.

### **중요 질문 ②. 컴프리헨션의 읽는 순서**

```python
[row for row in dev_rows]
```

`dev_rows`에서 데이터를 하나씩 꺼내 `row`에 할당하고 결과 리스트에 저장한다.

### **중요 질문 ③. 토크나이저 대화 템플릿**

```python
tokenizer.apply_chat_template(
	messages,
		add_generation_prompt=True
)
```

| 코드                           | 의미               |
| ---------------------------- | ---------------- |
| `apply_chat_template()`      | 모델에 맞는 대화 템플릿 적용 |
| `add_generation_prompt=True` | 답변 생성 시작 표시 추가   |
