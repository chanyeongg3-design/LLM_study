### 오늘 이해한 핵심

- **양자화(Quantization)** 는 모델의 가중치를 적은 비트로 표현해 저장 메모리를 줄이는 기술이다.
- **LoRA**는 기존 모델 가중치를 고정하고 작은 추가 행렬만 학습한다.
- **QLoRA**는 기반 모델을 4비트로 양자화한 뒤 LoRA 어댑터만 학습한다.
- **NF4**는 정규분포 형태의 가중치에 적합하도록 설계된 4비트 표현 방식이다.
- 모델의 **저장 자료형과 계산 자료형은 서로 다를 수 있다.**
- 학습 손실이 감소했다고 실제 답변의 정확도가 출력 형식이 반드시 개선되는 것은 아니다.

### 중요하게 구분할 개념

| 구분 | LoRA | QLoRA |
|---|---|---|
| base 모델 | 일반 정밀도 | 4비트 양자화 |
| base 가중치 학습 | X | X |
| 학습 대상 | LoRA A/B 행렬 | LoRA A/B 행렬 |
| 주요 목적 | 학습 파라미터 절감 | base 모델 메모리 절감 |
| 추가 처리 | LoRA 삽입 | 양자화 로딩 및 k-bit 학습 준비 |

## 2. 핵심 개념

### 2-1. 양자화(Quantization)

**쉬운 설명**

모델이 가지고 있는 숫자를 더 적은 비트로 표현해 저장하는 방법이다.

예를 들어 가중치 하나를 표현할 때의 이론적인 데이터 크기는 다음과 같다.

| 자료형 | 가중치당 비트 |
|---|---:|
| FP32 | 32bit |
| FP16/BF16 | 16bit |
| INT8 | 8bit |
| 4bit | 4bit |

4비트 표현은 FP16보다 가중치당 저장 공간이 이론적으로 **75% 작다.** 단, 실제 GPU 사용량에는 scale, 비양자화 층, 활성값, 어댑터 등 추가 메모리가 포함된다.

**왜 필요한가**

- VRAM이 제한된 GPU에서도 더 큰 모델을 다룰 가능성을 높이기 위해서다.

**핵심**

- 양자화는 모델 전체의 GPU 사용량을 무조건 75% 줄이는 기술이 아니다.

### 2-2. NF4와 Double Quantization

**NF4 (NormalFloat 4-bit)**

- 4비트를 이용해 16개의 대표값을 표현한다.
- 정규분포 형태의 가중치에 적합하도록 설계되었다.
- 원래 실수 가중치를 근사하므로 복원 오차가 발생할 수 있다.

**Double Quantization**

양자화할 때 사용하는 scale 값까지 다시 양자화해 추가 저장 공간을 절약하는 방법이다.

```python
quantization_config = BitAndBytesConfig(
    load_in_4bit=True,                     # 기반 선형층을 4비트로 로딩
    bnb_4bit_quant_type="nf4",             # NF4 양자화 적용
    bnb_4bit_use_double_quant=True,        # scale도 추가 양자화
    bnb_4bit_compute_dtype=COMPUTE_DTYPE,  # 계산 자료형
    bnb_4bit_quant_storage=torch.uint8,    # 저장 컨테이너
)
```

**주의할 점**

`torch.uint8`은 4비트 값을 담는 저장 컨테이너이며, 모델 전체가 8비트로 양자화된다는 의미가 아니다.

### 2-3. 저장 자료형과 계산 자료형

QLoRA는 가중치를 4비트로 저장해도 행렬 연산에는 BF16이나 FP32 같은 계산 자료형을 사용할 수 있다.

| 구분 | 의미 |
|---|---|
| `bnb_4bit_quant_type` | 양자화 표현 방식 |
| `bnb_4bit_quant_storage` | 압축된 데이터를 담는 자료형 |
| `bnb_4bit_compute_dtype` | 양자화 층의 계산 정밀도 |

**핵심:** 4비트 저장과 4비트 계산은 같은 말이 아니다.

### 2-4. QLoRA와 LoRA의 관계

LoRA는 base 가중치 W에 작은 행렬 A와 B로만 업데이트를 추가한다.

\[
h = Wx + \frac{\alpha}{r}BAx
\]

- **W:** Base 모델 가중치
- **A, B:** 학습 가능한 LoRA 행렬
- **r:** 저랭크 행렬의 차원
- **alpha:** 업데이트 크기를 조절하는 값

QLoRA에서도 학습하는 것은 A와 B다. 차이는 **base 가중치 W를 양자화된 형태로 저장하고 사용한다는 점**이다.

### 2-5. Gradient Checkpointing

**쉬운 설명**

학습 과정에서 사용하는 중간 계산 결과를 모두 저장하지 않고, 필요한 일부만 역전파 시점에 다시 계산하는 기술이다.

- **장점:** 활성값 메모리 절약
- **단점:** 재계산으로 학습 시간이 증가할 수 있음
- **이번 설정:** `use_reetrant=False`

디스크에 학습 상태를 저장하는 일반적인 checkpoint와 목적이 다르다.

### 블록 1 — 기존 실험 결과 검증

```python

    raise FileNotFoundError(
        "4장의 lora_report.json을 업로드하세요."
    )

# 데이터 ZIP 내용을 SHA-256으로 계산
data_sha256 = hashlib.sha256(
    Path("training_data_zip").read_bytes()
).hexdigest()

# 이전 실험 데이터와 동일한지 검사
if lora_report["data_sha256"] != data_sha256:
    raise ValueError("4장과 다른 데이터 ZIP입니다.")
```

- **기능:** 비교할 실험의 데이터 동일성 검증
- **입력:** `lora_report.json`, `training_data.zip`
- **처리:** 파일 존재 여부 및 해시 비교
- **결과:** 조건이 다르면 실험 중단

## 5. LoRA와 QLoRA 실험 비교

| 평가 항목 | LoRA | QLoRA |
|---|---:|---:|
| 학습 가능 파라미터 | 540,672 | 540,672 |
| 학습 전 Dev Loss | 0.9207 | 1.0459 |
| 학습 후 Dev Loss | **0.8717** | 0.9745 |
| 형식·인용 검사 | 0/12 | 0/12 |
| 최대 할당 메모리 | 1.615 GiB | 1.637 GiB |
| 학습 시간 | **18.5초** | 25.3초 |

### 결과 해석

**1. 두 방식 모두 학습 손실이 감소했다.**

다만 시작 loss부터 다르므로 최종 loss 차이만으로 학습 방식 전체의 우열을 판단하기는 어렵다.

**2. QLoRA가 메모리를 더 적게 사용하지 않았다.**

이번 0.5B 모델의 학습 구간에서는 QLoRA의 최대 할당 메모리가 오히려 **0.022 GiB 높았다.**

이는 QLoRA가 일반적으로 메모리를 줄일 수 없다는 뜻이다. 모델 크기, 활성값, 비양자화 파라미터, 측정 범위가 영향을 준다.

**3. QLoRA의 학습 시간이 더 길었다.**

이번 실험에서 QLoRA는 LoRA보다 **6.8초 더 소요되었다.**

**4. 손실 감소와 출력 품질은 다르다.**

두 방식 모두 dev 12개 문항의 형식, 인용 검사에서 **0개 통과했다.**

QLoRA 출력에서는 status 누락, 잘못된 인용 ID, 질문의 70,000원 금액 조건 미비교 등이 관찰되었다.

즉, 모델이 정답 토큰의 확률을 개선하더라도 실제 업무 요구사항을 만족하는 답변을 생성한다고 보장할 수 없다.

## 6. 프로젝트 활용

### 적용할 곳

- 로컬 LLM 파인튜닝 실험
- 금융 챗봇의 생성 모델 개선 실험
- RAG 시스템에서 검색 문서를 기반으로 답변을 생성하는 모델의 형식 준수 평가

### 적용할 방법

1. 동일 모델과 데이터에서 LoRA, QLoRA 설정을 통제해 비교한다.
2. 모델 저장 메모리와 학습 중 최대 GPU 메모리를 분리해 관찰한다.
3. Dev Loss뿐 아니라 JSON형식, 인용 ID, 조건 총족 여부를 함께 평가한다.
4. 저장한 어댑터를 새로운 세션에 복원해 생성 결과의 logits를 검증한다.
5. 모델 크기를 확장하면서 양자화의 실질적인 메모리 절감 효과를 확인한다.

### 적용 후 확인할 지표

| 지표 | 확인 목적 |
|---|---|
| Dev Loss | 학습 과정의 손실 변화 |
| 형식 통과율 | 출력 계약 준수 여부 |
| 인용 ID 통과율 | 허용된 출처 형식 준수 여부 |
| Peak GPU Memory | 학습 중 최대 메모리 |
| Training Time | 학습에 걸린 시간 |
| 복원 일치 검사 | 저장 및 재로딩의 재현성 |

## 7. 오늘의 최종 정리

오늘 가장 중요하게 이해한 점은 **QLoRA가 단순히 모델 전체를 4비트로 바꾸는 학습 방식이 아니라는 것이다.**

base 모델은 NF4로 양자화해 보관하고, 학습 전 필요한 처리를 수행한 후 LoRA 어댑터만 업데이트한다.

또한 모델이 작은 경우에는 양자화로 절약한 메모리보다 추가 처리 비용과 다른 메모리 사용 요소가 더 두드러질 수 있다는 점을 비교 결과에서 확인했다.

앞으로 파인튜닝 성능을 평가할 때는 **Loss, 답변 품질, 메모리, 학습 시간, 재현성**을 독립적으로 살펴보는 것이 중요하다.
