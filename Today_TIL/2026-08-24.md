# ❓ 왜 필요한가?
1. 손실 함수는 왜 필요한가?
- 모델의 예측값과 정답값의 차이를 숫자로 계산하여 모델이 얼마나 틀렸는지 판단하기 위해 필요하다
1. 문제 유형에 따라 Loss를 다르게 사용하는 이유는?
- 회귀, 이진 분류, 다중 분류는 정답의 형태와 모델의 출력 방식이 다르기 때문에 적잘한 Loss를 선택해야 한다. 
1. Optimizer는 왜 필요한가?
- ‘backward()’ 에서 계산된 gradient를 이용해 실제 parameter를 업데이트하기 위해 필요하다.

# 🧠 핵심 개념
손실 함수 → 모델 예측과 정답의 차이를 계산
문제 유형별 Loss: 
- 회귀 → ‘MSELoss’
- 이진 분류 → ‘BCEWithLogitsLoss’
- 다중 분류 → ‘CrossEntropyLoss’
Optimizer:
- ‘SGD’
- ‘Adam’
Learning Rate:
- parameter를 한 번에 얼마나 크게 업데이트할지 결정
- 너무 작으면 학습이 느림
- 너무 크면 loss가 흔들리거나 발산할 수 있음
학습 흐름:
zero_grad → forward → loss → backward → step
각 단계의 역할: 
- zero_grad() → gradient 초기화
- model(input) → 예측값 계산
- criterion(output, targets) → loss 계산
- loss.backward() → gradient 계산
- optimizer.step() → parameter 업데이트 


# 💻 직접 작성한 코드

```Plain Text
import torch
import torch.nn as nn
import torch.optim as optim

# 예측값과 정답값
pred = torch.tensor([[2.5], [3.0], [4.0]])
target = torch.tensor([[3.0], [2.0], [5.0]])

# MSE를 직접 계산
manual_loss = ((pred - target) ** 2).mean()

# PyTorch의 MSELoss 사용
torch_loss = nn.MSELoss()(pred, target)

# 직접 계산한 loss와 PyTorch loss 비교
print(manual_loss, torch_loss)
print(torch.allclose(manual_loss, torch_loss))

🔎 실행 결과
manual_loss 와 torch_loss의 값이 동일하게 계산됨

torch.allclose(manual_loss, torch_loss) -> True

```
```Plain Text
# SGD Optimizer
optimizer = optim.SGD(
		model.parameters(),
		lr=0.01,
		momentum=0.9
)
```
```Plain Text
# Adam Optimizer
optimizer = optim.Adam(
		model.parameters(),
		lr=0.001
)
```
```Plain Text
# PyTorch 학습 step

# 1. 이전 gradient 초기화
optimizer.zero_grad() 

# 2. 모델 예측
outputs = model(inputs)

# 3. loss 계산
loss = criterion(outputs, targets)

# 4. gradient 계산
loss.backward()

# 5. parameter 업데이트
optimizer.step()
```
```Plain Text
학습 과정:
zero_grad() -> 이전 gradient 초기화

forward -> 예측값 생성

loss -> 현재 오차 계산

backward() -> gradient 계산

step() -> parameter 업데이트 
```
# 🤔 내가 헷갈릴만한 부분
- manual_loss는 MSE를 직접 계산한 값이고 torch_loss는 nn.MSELoss()로 계산한 값이다.
- loss만 계산한다고 parameter가 업데이트 되는 것은 아니다.
- backward()는 gradient를 계산하고 실제 parameter는 바꾸지 않는다.
- 실제 parameter를 변경하는 단계는 optimizer.step()이다.
- zero_grad를 하지 않으면 gradient가 누적될 수 있다.
- CrossEntropyLoss의 target 숫자는 예측할 실제 숫자가 아니라 class의 index이다.
- BCEWithLogitsLoss에서는 일반적으로 마지막 sigmoid를 직접 넣지 않는다.
- model.parameters()를 통해 optimizer가 업데이트할 parameter를 전달한다.
- lr은 Learning Rate를 의미한다
- momentum은 이전 gradient의 방향을 일부 반영한다.
