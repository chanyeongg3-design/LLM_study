## 1) LangChain

- 정의: LangChain은 LLM 애플리케이션의 여러 작업을 역할별 구성 요소로 나누고 연결하는 프레임워크이다.
- LangChain 자체가 새로운 AI 모델인 것은 아니다.\
- LLM 앱의 코드 구조를 체계적으로 구성
쉽게 말해:
LLM 앱을 만들 떄 모든 코드를 한곳에 작성하지 않고 역할별로 분리해 연결할 수 있게 해주는 도구이다. 

LangChain 기본 구조

```text
[사용자 입력]
      ↓
   [Prompt]
      ↓
    [Model]
      ↓
   [Parser]
      ↓
[앱에서 사용할 결과]
```

- Prompt : 모델에게 전달할 입력 생성
- Model : LLM 호출
- Parser : LLM 응답을 앱에서 쓰기 좋은 형태로 변호나

### 왜 필요한가?

LLM 애플리케이션이 커지면 다음 단계들이 추가될 수 있다.

- Prompt
- Model
- Parser
- Retriever
- Memory
- Tool
- Callback
LangChain을 사용하면 이런 기능을 각 단계로 분리해서 연결하기 쉽다.

### 어디에 쓰이는가?

- 챗봇
- RAG
- AI Agent
- 문서 요약
- 정보 추출
- 분류
- 여러 단계의 LLM 파이프라인

## 2) Prompt Template

Prompt Template은 고정된 Prompt 구조를 만들어두고 필요한 값만 바꿔 재사용하는 방식이다.

```python
from langchain_core.prompts import PromptTemplate

prompt = PromptTemplate.from_template(
	"{topic}을 초보자에게 쉽게 설명해주세요."
)

result = prompt.format(topic="LangChain")

print(result)
```

결과: LangChain을 초보자에게 쉽게 설명해주세요.

### 왜 필요한가?

매번 Prompt 전체를 새로 작성하지 않고 [고정 문장 + 변경되는 값] 구조로 괸리할 수 있다. 

PromptTemplate vs ChatPromptTemplate

| 개념                 | 결과         | 사용 상황          |
| ------------------ | ---------- | -------------- |
| PromptTemplate     | 문자열        | 단순 텍스트 Prompt  |
| ChatPromptTemplate | 역할이 있는 메시지 | Chat Model 사용  |
```python
from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_messages([
    (
        "system",
        "너는 초보자를 가르치는 AI 튜터야."
    ),
    (
        "human",
        "{question}"
    ),
])

messages = prompt.format_messages(
    question="LangChain이 뭐야?"
)
```


system
→ 모델의 역할과 공통 규칙
너는 친철한 AI 튜터야

human
→ 사용자의 실제 질문 
LangChain이 뭐야?

처럼 모델에게 전달된다.

## 3) Model

Prompt에서 만든 메시지를 실제 LLM에게 전달한다.
LangChain에서는 OpenAI 모델을 사용할 때 ChatOpenAI를 사용할 수 있다.

```python
from langchain_openai import ChatOpenAI

model = ChatOpenAI(
	model="사용할 모델"
)

respone = model.invoke(messages)
```

중요한 점: response = model.invoke(message)의 결과는 일반 문자열이 아니라 AIMessage 이다.
따라서: print(response) 보다 실제 답변 본문만 필요한 경우: print(response.content) 처럼 사용한다.

```text
Prompt
   ↓
messages
   ↓
model.invoke()
   ↓
AIMessage
   ↓
.content
   ↓
실제 답변
```

### 왜 AIMessage를 사용할까?

응답에는 단순한 답변 문장 외에도 추가 정보가 들어갈 수 있기 때문이다. 

```text
AIMessage
├─ content
└─ 기타 부가 정보

구조라고 생각하면 된다
```


## 4) Output Parser

Output Parser는 LLM이 반환한 결과를 애플리케이션에서 사용하기 좋은 PYthon 자료형으로 바꾸는 역할을 한다.

AIMessage → Parser → str / list / dict

| parser                      | 결과         | 사용 예    |
| --------------------------- | ---------- | ------- |
| StrOutParser                | str        | 설명, 요약  |
| CommaSeparatedListOutParser | list[str]  | 태그, 키워드 |
| JsonOutputParser            | dict, list | 구조화된 정보 |
### StrOutputParser

```python
from langchain_core.output_parsers import strOutputParser

parser = StrOutputParser()

result = parser.invoke(response)
```

```
AIMessage
	↓
StrOutputParser
	↓
"LangChain은 ..."
```

즉 AIMessage → 문자열로 바꿔준다.

### JSON Parser

LLM에게 여러 값을 구조적으로 받고 싶을 때 사용할 수 있다. 

예:

```json
{
  "category": "AI",
  "difficulty": "beginner"
}
```

이것을 Python에서는:

```python
{
    "category": "AI",
    "difficulty": "beginner"
}
```

같은 dict로 사용할 수있다. 하지만 중요한 점이 있다.
| Parser는 모델이 반드시 올바른 형식으로 답하도록 강제하는 기능이 아니다.

따라서 
```
Prompt
→ 어떤 형식으로 답해야 하는지 안내

Parser 
→ 실제 응답을 python 값으로 변환
```

두 단계가 필요

```
필요한 자료형 결정
		↓
	Parser 선택
		↓
형식 안내를 Prompt에 추가
		↓
	LLM 호출
		↓
	Parser 변환
		↓ 
필요한 Key / 값 확인
```

이렇게 하면 프로젝트끼리 패키지 버전이 충돌하는 것을 줄일 수 있다.

      ↓

## 7) 개념 간 차이

OpenAI SDK vs LangChain

| 구분     | OpenAI SDK  | LangChain                  |
| ------ | ----------- | -------------------------- |
| 특징     | 모델 직접 호출    | 단계를 나눠 호출                  |
| 구조     | 직접 코드 구성    | Prompt / Model / Parser 분리 |
| 적합한 경우 | 단순한 한 번의 호출 | 여러 단계가 있는 LLM 앱            |
| 확장     | 직접 구현       | Retriever, Memory 등 연결     |

OpenAI SDK : 

```

→ API 호출
→ 응답 호출

과정을 직접 작성한다.
```

LangChain : 

```
Prompt
→ Model
→ Parser

처럼 역할을 나눈다. 
```

### Prompt / Model / Parser

| 개념     | 역할                   |
| ------ | -------------------- |
| Prompt | LLM에게 보낼 입력 생성       |
| Model  | 실제 LLM 호출            |
| Parser | LLM 응답을 원하는 자료형으로 변환 |
한 마디로 : 

```
Prompt = 질문 준비
Model = 질문 전달 및 답변 생성

```

### 8) 실제 LLM프로젝트에서는 어떻게 사용되는가? 

LangChain의 기본 구조는 이후 RAG와 AI Agent의 기초가 된다.

### 기본 LLM App

```text
사용자 질문
    ↓
Prompt
    ↓
LLM
    ↓
Parser
    ↓
최종 답변
```

### 이후 RAG로 확장하면

```text
사용자 질문
     ↓
Retriever
     ↓
관련 문서 검색
     ↓
Prompt
     ↓
LLM
     ↓
Parser
     ↓
최종 답변
```

즉 지금 배우는:

```text
Prompt → Model → Parser
```

는 나중에 RAG 구조의 중심에 그대로 들어간다.

## 11) 내가 설명할 수 있어야 하는 질문

### 1. LangChain은 LLM 모델 자체와 어떤 차이가 있는가?

LangChain은 그자체로 AI모델이 아니라, LLM을 활용해 유용한 애플리케이션을 쉽게 만들 수 있도록 돕는 '개발 프레임워크(도구모음)' 이다.

### 2. Prompt → Model → Parser 각각의 역할은 무엇인가?

이 세가지는 AI 애플리케이션(특히 LangChain 프레임워크)에서 데이터가 처리되는 가장 기본적인 '입력 → 생성 → 출력 가공' 파이프라인을 구성한다. 

역할
- Prompt(프롬프트 템플릿) : 사용자의 단순한 질문을 AI가 의도대로 움직일 수 있도록 구체적인 '작업 지시문'으로 포장한다.
- Model(LLM) : 프롬프트를 읽고 방대한 지식과 추론 능력을 바탕으로 실제 텍스트 답변을 생성한다.
- Parser(출력 파서) : 모델이 뱉어낸 '단순 줄글' 텍스트에서 핵심만 골라내어 프로그램(코드)이 다루기 쉬운 데이터 구조(JSON 등)로 변환한다. 

### 3. PromptTemplate과 ChatPromptTemplate의 차이는 무엇인가?

#### - PromptTemplate(단일 텍스트 형태)
단순하게 빈칸(변수)이 뚫려 있는 하나의 문장 템플릿이다. AI에게 부여할 페르소나와 사용자의 질문을 하나로 뭉쳐서 단순한 문자열로 모델에 전달한다.

특징: 복잡한 대화 맥락을 유지하기 어렵고, 모델이 어디까지가 지시사항이고 어디부터가 사용자 입력인지 헷갈릴 수 있다.

#### - ChatPromptTemplate(메시지 배열 형태)
현대의 AI 모델들은 대화의 맥락을 잘 이해하도록 역할 기반으로 훈련되어 있다. 이를 위해 메시지를 구조화하여 전달하는 템플릿이다.

가장 핵심적인 차이는 데이터를 전달하는 형태(구조)이다.


### 4. model.invoke( )의 결과가 바로 문자열이 아닌 이유는 무엇인가?
최신 AI 모델이 텍스트 답변뿐만 아니라 비용 계산, 디버깅, 외부 도구 실행에 필요한 부가 정보(메타데이터)를 함께 반환하기 때문이다. 

LangChain의 대화형 모델은 실행결과를 AIMessage 라는 규격화된 객체에 담아서 돌려준다.
이 객체 안에는 content, response_metadata, tool_calls 등과 같은 핵심 정보들이 포함되어 있다.

- 내용(content) : 우리가 실제로 확인하려는 AI의 텍스트 답변
- 메타데이터(response_metadata) : 답변을 생성하는데 소비된 토큰 개수, AI가 답변을 멈춘 이유, 사용된 모델 버전 등 시스템 관리에 과금에 필수적인 데이터이다.
- 도구 호출(tool_calls) : AI가 단순 답변을 넘어 검색, 계산기, 사내 API 등 외부 도구를 사용하기로 결정했을 때, 어떤 함수를 어떤 값으로 실행할지에 대한 구체적인 명령 데이터이다. 

Parser(출력 파서)가 바로 이 복잡한 AIMessage 객체에서 우리가 원하는 content 텍스트만 깔끔하게 뽑아내거나, 특정 데이터 구조를 변환해 주는 역할을 담당한다. 

### 5. Output Parser는 왜 필요한가?
Output Parser가 필요한 가장 큰 이유는 AI가 만들어내는 '사람의 언어(자연어 텍스트)' 나 '복잡한 객체'를 컴퓨터가 즉시 활용할 수 있는 '구조화된 데이터'로 번역하기 위해서이다. 

모델이 '생각하고 대답하는 역할' 이라면, Output Parser는 그 대답을 가져다 '우리 프래그램의 부품으로 끼워 맞출수 있게 규격화하는 마감 작업' 이라고 할 수 있다. 

### 6. Parser만 사용한다고 모델이 원하는 JSON 형식을 반드시 지키는 것은 아닌 이유는 무엇인가?
Parser(파서)는 모델이 이미 만들어낸 텍스트 결과물을 '사후에 해석'하는 도구일 뿐, 모델의 텍스트 생성 과정 자체를 물리적으로 강제할 수는 없기 때문이다. 

이 문제를 해결하고 파서가 안전하게 작동하도록 보장하려면, 모델이 처음부터 규칙에 맞는 텍스트를 뱉어내도록 유도하는 과정이 반드시 필요하다.

- 구조화딘 프롬프팅(Structured Prompting) : 파서가 요구하는 정확한 데이터 스키마와 규칙을 프롬프트에 주입해야한다.

- 모델 단의 출력 강제 (JSON 모드 / 도구 호출) : 프롬프트 지시만으로는 가끔 모델이 실수를 할 수 있다. 이를 원천 차단하기 위해 최근 모델들은 디코딩 파라미터 레벨에서 출력을 강제하는 'JSON 모드'를 제공하거나, 응답을 특정 스키마에 무조건 맞추도록 하는 '도구 호출(Tool/Function Calling)' 기능을 지원한다.

즉, 성공적인 구조화 데이터를 얻으려면 '프롬프트를 통한 명확한 지시'와 '파서를 통한 깔끔한 추출'이 한세트로 맞물려 돌아가야 한다. 


## 7. `.env`와 `.venv`는 각각 어떤 역할을 하는가?
.env는 비밀번호나 설정값을 보관하는 '파일'이고, .venv는 프로젝트 전용 라이브러리를 설치하는 '격리된 폴더'이다.
## `.env` (환경 변수 파일)

- **역할:** API 키, 데이터베이스 비밀번호 등 소스 코드에 직접 노출되면 안 되는 **민감한 정보(환경 변수)를 저장**하는 텍스트 파일입니다.
    
- **특징:** 코드를 깃허브(GitHub) 등에 공유할 때 해킹을 방지하기 위해 반드시 `.gitignore`에 추가하여 업로드되지 않도록 막아야 합니다. (대신 `.env.example` 같은 빈 틀만 공유합니다.)
    

## `.venv` (가상 환경 폴더)

- **역할:** 해당 프로젝트에서만 사용할 파이썬 패키지(라이브러리)들을 모아두는 독립된 작업 공간(Virtual Environment)입니다.
    
- **특징:** A 프로젝트에서는 구버전 패키지를, B 프로젝트에서는 최신 패키지를 사용할 때 서로 충돌이 발생하지 않도록 각 프로젝트의 환경을 격리해 줍니다. 용량이 크고 사용자의 운영체제마다 내부 파일이 달라지므로, 이 폴더 역시 깃허브에 올리지 않습니다.


## 8. LangChain의 기본 구조가 이후 RAG에 어떻게 연결되는가?
LangChain의 기본 뼈대인 Prompt → Model → Parser 파이프라인의 앞단에 Retriever를 끼워 넣어 프롬프트에 지식 재료를 공급하는 방식으로 RAG가 완성된다. 

기본 구조에서는 사용자의 질문만 프롬프트에 들어갔다면, RAG 구조에서는 Retriever가 찾아온 외부 정보가 프롬프트의 빈칸에 함께 주입되는 것이 가장 핵심적인 연결 고리이다. 

### RAG로 확장된 데이터 파이프라인 흐름

1. **Retriever (정보 검색):** 사용자가 질문을 던지면, 모델에게 가기 전에 먼저 Retriever가 사내 문서나 벡터 데이터베이스를 뒤져서 질문과 관련된 텍스트 조각(Document)들을 찾아옵니다.
    
2. **Prompt (정보 주입):** PromptTemplate은 이제 사용자의 질문 하나만 받는 것이 아니라, 두 개의 빈칸을 채워 넣도록 설계됩니다.
    
    - `Context` (참고자료): Retriever가 방금 찾아온 팩트 정보
        
    - `Question` (질문): 사용자의 원래 질문
        
    - _프롬프트 지시문 예시: "반드시 아래 제공된 Context만 참고해서 Question에 답해."_
        
3. **Model (팩트 기반 생성):** 모델은 프롬프트에 함께 포장된 '참고 자료'를 읽고, 환각(거짓말) 없이 팩트에 기반한 텍스트 답변을 생성해 냅니다.
    
4. **Parser (구조화):** 모델이 만든 텍스트 답변을 프로그램이 화면에 띄우거나 다음 자동화 로직으로 넘기기 좋게 구조화된 데이터(JSON 등)로 변환합니다.

## 9. 오늘의 한 줄
- LangChain은 LLM 자체를 바꾸는 기술이 아니라, Prompt → Model → Parser 처럼 LLM 애플리케이션의 각 단계를 역할별로 분리하고 연결해 확장하기 쉽게 만드는 프레임워크이다. 

이번 범위에서 가장 중요한 한 가지를 고르면 Prompt → Model → Parser 흐름이다.
앞으로 LCEL, RAG, Agent를 배울 때도 이 기본 구조 위에 기능이 하나씩 추가된다고 생각하면 이해하기 쉽다.
