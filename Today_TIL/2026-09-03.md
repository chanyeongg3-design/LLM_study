## 📚 Self-Attention의 원라와 Multi-Head Attention Shape
핵심 흐름: 
문맥의 필요성 → Q·K·V → Score → Mask → Softmax → Context → Multi-Head Attention

- Attention Weight와 Context Vector의 의미를 학습했다.
- Tensor 연산으로 간단한 Self-Attention을 구현했다.
- Multi-Head Attention의 Head 분리·결합 Shape을 확인했다.
- Padding Mask와 Attention 구현에서 자주 발생하는 오류를 정리했다. 
> 핵심은 공식을 외우는 것이 아니라 각 단계의 입력·출력 Shape과 역할을 연결하는 것이다. 
```Plain Text
입력 토큰 표현 X

→ Output Projection
```
## 2. Self-Attention이 필요한 이유
### 2-1. Token ID만으로는 문맥이 완성되지 않는다.
Tokenizer는 문장을 Token ID로 바꾼다. 
하지만 Token ID는 어떤 토큰인지를 나타낼 뿐, 현재 문장에서 그 토큰이 어떤 의미로 사용되었는지까지 완성하지는 않는다. 
같은 토큰이라도 주변 문맥에 따라 참고해야 할 대상과 의미가 달라진다.
Self-Attention은 각 토큰이 다른 토큰을 참고하여 자신의 벡터 표현을 문맥에 맞게 업데이트하는 과정이다.  
```Plain Text
기본 토큰 표현
+ 주변 토큰과의 관계
= 문맥이 반영된 토큰 표현
```
Self-Attention은 Token ID를 새로운 ID로 바꾸는 과정이 아니다.
각 토큰의 벡터 표현을 문맥에 맞게 바꾸는 과정이다. 
## 3. **Query·Key·Value**
### 3-1. **Q·K·V의 역할**
Self-Attention은 현재 토큰이 다른 토큰 중 무엇을 얼마나 참고할지를 계산한다. 

> Query가 실제 자연어 질문으로 저장되는 것은 아니다.
> 학습된 벡터가 질문과 비슷한 역할을 수행한다고 이해하면 된다. 
### 3-2. **Q·K·V는 같은 입력에서 출발한다.**
Self-Attention에서는 **Q·K·V**가 모두 동일한 입력 x에서 출발한다. 
```Plain Text
Q = XW_Q
K = XW_K
V = XW_V
```
하지만 서로 다른 학습 가능한 Projection을 통과하기 때문에 결과와 역할은 달라진다. 
```Plain Text
입력 X
├─ W_Q → Query
├─ W_K → Key
└─ W_V → Value
```
```Python
import torch
from torch import nn

B = 2
L = 5
D_MODEL = 8

# Shape: [B, L, D_MODEL]
x = torch.randn(B, L, D_MODEL)

q_proj = nn.Linear(D_MODEL, D_MODEL, bias=False)
k_proj = nn.Linear(D_MODEL, D_MODEL, bias=False)
v_proj = nn.Linear(D_MODEL, D_MODEL, bias=False)

q = q_proj(x)
k = k_proj(x)
v = v_proj(x)

print("x:", x.shape) # [2, 5, 8]
print("q:", q.shape) # [2, 5, 8]
print("k:", k.shape) # [2, 5, 8]
print("v:", v.shape) # [2, 5, 8]
```
Projection은 Token ID를 변경하는 과정이 아니다
동일한 토큰 표현을 Query·Key·Value라는 서로 다른 관점의 표현으로 변환하는 선형변환이다. 
## 4. Scaled Dot-Product Attention
### 4-1. 전체 공식
```Plain Text
Attention(Q, K, V) = softmax(QKᵀ / √dₖ) V
```
계산 과정은 네 단계로 나눌 수 있다. 
```Python
1. Q와 K를 비교해 Score 계산 # QKᵀ
2. Score를 √dₖ로 나눠 Scaling # √dₖ
3. Softmax로 Attention Weight 생성 # softmax
4. Weight만큼 Value를 섞어 Context 생성 # V
```
Mask가 필요하다면 Scaling과 Softmax 사이에 적용한다. 
```Plain Text
Q @ Kᵀ
→ Scaling
→ Mask
→ Softmax
→ Weight @ V
```
### 4-2. Score 계산

`Score = QKᵀ` 
Q와 K의 Shape이 [B, L, D]라면 K의 마지막 두 축을 교환한다.
```Plain Text
Q    : [B,L,D]
Kᵀ   : [B,D,L]
Score: [B,L,L]
```
**Score Matrix의 의미:**
- 행: 표현을 업데이트하려는 Query
- 열: 참고 대상인 Key
- 각 칸: Query와 Key의 정규화 전 관련도 
**Score는 확률이 아니다.** 
- 음수가 될 수있다.
- 값의 합이 1일 필요가 없다.
- 아직 참고 비율로 정규화되지 않았다.
### 4-3. Scaling

`Scaled Score = Score / √dₖ`
Query와 Key의 차원 `dₖ` 가 커지면 Dot Product의 절댓값도 커질 가능성이 있다.
큰 값을 그대로 Softmax에 넣으면 특정 위치에 Weight가 지나치게 집중될 수 있다.
Scaling은 다음 효과를 가진다.
- Score의 크기를 완화한다. 
- Softmax가 지나치게 뾰족해지는 형상을 줄인다.
- Gradient와 학습을 더 안정적으로 만든다.
Scaling은 Score의 순위를 바꾸는 과정이 아니다.
전체적인 값의 크기를 조절하는 과정이다.
Multi-Head-Attention에서는 전체 D_model이 아니라 Head 하나의 차원인 D_head를 사용한다.
`Scaling = √D_head` 
### 4-4.  Softmax
```Python
weights = torch.softmax(
    scaled_scores,
    dim=-1,
)
```
Score Shape이 다음과 같다고 하자.
`[B,H,L_query,L_key]` 
마지막 축은 각 Query가 비교하는 Key 후보 축이다. 
따라서 dim=-1에 Softmax를 적용한다.
Softmax 적용 후:
- 모든 Weight는 0과 1사이가 된다.
- Query 한 행의 Weight 합은 1이 된다.
- 상대적으로 높은 Score가 더 큰 Weight를 얻는다. 
- `weights.sum(dim=-1) ≈ 1`
### 4-5. Value 가중합
`Context = Attention Weight x Value` 
```Python
Weight : [B,L_query,L_key]
Value  : [B,L_key,D_value]
Context: [B,L_query,D_value]
```
Context Vector는 특정 Value 하나를 그대로 복사한 것이 아니다.
여러 위치의 Value를 Attention Weight에 따라 섞어 만든 새로운 문맥 표현이다.
## 5. Attention Weight와 Context Vector
### 5-1. Attention Weight의 의미
다음과 같은 Attention Weight가 있다고 하면
```Plain Text
"먹었다" Query의 Attention Weight

민수는      0.25
식당에서    0.15
라면을      0.45
먹었다      0.15
합계        1.00

이 경구 Context Vector는 다음처럼 계산한다
= 0.25 × 민수 정보
+ 0.15 × 식당 정보
+ 0.45 × 라면 정보
+ 0.15 × 행동 정보
```
이 Context에는 행동의 주체·장소·대상·행동 정보가 함께 반영된다. 
### 5-3. Attention Weight는 정답 확률이 아니다.
Attention Weight가 높다고 해서 해당 토큰이 모델의 최종 예측에서 가장 중요한 단어라고 단정할 수 없다.
Attention Weight는 특정 Layer와 특정 Head에서 Value를 섞는데 사용한 비율이다.
최종 예측에는 다음 요소도 영향을 준다.
- 다른 Attention Head
- 다른 Transformer Layer
- Residual Connection
- Feed Forward Network
- Layer Normalization
- 최종 출력 Head
> Attention Heatmap은 절대적인 설명이라기보다 모델의 동작을 관찰하는 단서로 사용해야 한다. 
## 6. Padding Mask
### 6-1. PAD를 제외해야 하는 이유
PAD 토큰은 실제 문맥이 아니므로 Key 후보에서 제외해야 한다.
이정리에서 사용하는 Mask의 의미는 다음과 같다. 
```Plain Text
True = 실제 토큰, 참고 가능
False = PAD, 참고 불가능
```
Mask는 Softmax 전에 Score에 적용한다. 
```Plain Text
PAD 위치의 Score
→ -inf
→ Softmax
→ Weight 0
```
Softmax를 적용한 뒤 PAD Weight를 0으로 바꾸면 남은 Weight의 합이 1이 아니게 된다.
따라서 Mask는 반드시 Softmax 전에 적용한다.
### 6-2. Mask Shape
Score Shape이 다음과 같다고 하면 
`[B,H,L_query,L_key]`  Head와 Query 축에 Broadcasting 하기 위해 다음처럼 확장한다.
```Plain Text
[B,L_key]
→ [B,1,1,L_key]
```
API마다 Boolean Mask의 True와 False 의미가 다를 수 있다.
직접 만든 함수와 PyTorch API가 동일한 Mask 규칙을 사용한다고 가정하지 말고, 각 API의 입력 계약을 확인해야 한다. 
## 7. Tensor로 Self-Attention 구현
```Python
import math
import torch

def simple_self_attention(
		x, 
		valid_key_mask=None, 
):
		
		# 입력 shape: [B, L, D]
		if x.ndim != 3:
				raise ValueError(
				f"x must have shape [B, L, D],"
				f"got {tuple(x.shape)}"
				)
		
		d_k = x.size(-1)
		
		# 교육용 단순화
		# 실제 모델에서는 서로 다른 Projection을 사용
		q = x
		k = x
		v = x
		
		# [B,L,D] → [B,D,L]
		k_t = k.transpose(-2, -1)
		
		# [B,L,D] @ [B,D,L]  → [B,L,L]
		scores = torch.matumul(q, k_t)
		
		# Score 크기 조절
		scaled_scores = scores / math.sqrt(d_k)
		
		if valid_key_mask is not None:
				if valid_key_mask.shape != x.shape[ :2]:
						raise ValueError(
								"valid_key_mask must have shape [B, L]"
						)
						
				if valid_key_mask.shape != torch.bool:
						raise TypeError(
								"valid_key_mask must be boolean"
						)
				
				# 모든 key가 가려지면 Softmax 결과가 NaN이 될 수 있으므로 차단 
				if not torch.all(
						valid_key_mask.any(dim=-1)
				):
				
						raise ValueError(
								"Each sample needs at least one valid key"
						)
				
				# [B,L] → [B,1,L]
				key_mask = valid_key_mask.unsqueeze(1)
				
				# PAD 위치를 Softmax 전에 제외
				scaled_scroes = scaled_scores.masked_fill(
						~key_mask,
						float("-inf"),
				)
		# 마지막 Key 축에 Softmax 적용
		weights = torch.sofrmax(
				scaled_scores,
				dim=-1,
		)
		# [B,L,L] @ [B,L,D] → [B,L,D]
		context = torch.matmul(
				weight,
				v,
		)
		
		assert context.shape == x.shape
		assert weight.shape == (
				x.size(0),
				x.size(1),
				x.size(1),
		)
		
		return context, weights 
```
```Plain Text
입력 x
[B,L,D]

→ K Transpose
[B,D,L]

→ Q @ Kᵀ
[B,L,L]

→ Scaling
[B,L,L]

→ Mask
[B,L,L]

→ Softmax
[B,L,L]

→ Weight @ V
[B,L,D]
```
## 8. Multi-Head Attention
### 8-1. 여러 Head를 사용하는 이유
Multi-Head Attention은 동일한 입력을 여러 Head가 서로 다른 Projection 공간에서 처리할 기회를 제공한다.
각 Head는 학습 결과에 따라 서로 다른 관계에 반응할 수 있다.
예를 들면 다음과 같다.
- 주어와 동사의 관계
- 수식어와 명사의 관계
- 가까운 토큰의 관계
- 멀리 떨어진 토큰의 관계
각 Head의 역할이 미리 고정된 것은 아니다. 
### 8-2. D_model, num_heads, D_head
전체 표현 차원은 Head 수로 균등하게 나뉜다. 
`D_head = D_model / num_heads` 
각 Head가 동일한 정수 차원을 가져야 하므로 다음 조건이 필요하다. 
`D_model % num_heads == 0` 
### 8-3. Head Split
입력 Shape: `[B,L,D_model]`  D_model을 Head와 Head 차원으로 나눈다. 
```Plain Text
[B,L,D_model]
→ [B,L,H,D_head]
→ [B,H,L,D_head]
```
transpose(1, 2)를 사용하는 이유는 Head 축을 앞으로 옮겨 여러 Head의 Attention을 병렬로 계산하기 위해서다.
### 8-4. Head Merge
Head별 Attention 계산이 끝나면 반대 순서로 결합한다.
```Plain Text
[B,H,L,D_head]
→ [B,L,H,D_head]
→ [B,L,D_model]
```
Head를 합친 후에는 W_O를 사용해 각 Head의 결과를 다시 섞는다.
```Plain Text
ncat(head₁, ..., headₕ)
→ W_O
→ 최종 출력
```
W_O가 없다면 Head 결과는 단순히 옆으로 이어 붙인 상태에 머문다. 
### 8-5. 전체 Shape 흐름
```Plain Text
입력 X
[B,L,D_model]

→ Q·K·V Projection
[B,L,D_model]

→ Head 분리
[B,H,L,D_head]

→ Score
[B,H,L_query,L_key]

→ Scaling·Mask·Softmax
[B,H,L_query,L_key]

→ Value 가중합
[B,H,L_query,D_head]

→ Head 결합
[B,L_query,D_model]

→ Output Projection W_O
[B,L_query,D_model]
```
## **10. MHA·MQA·GQA**
Decoder-only LLM에서는 Query Head 수와 K/V Head 수가 다를 수 있다. 

Query Head 4개가 하나의 K/V Head를 공유한다.
KV Cache의 크기는 Query Head 수인 H_q보다 K/V Head 수인 H_kv에 직접 영향을 받는다.
따라서 MQA와 GQA는 LLM 생성 과정에서 KV Cache 메모리를 줄이는 데 유리하다.

## 14. 직접 설명해보기
### Q1. Self-Attention이 필요한 이유?
Token ID와 기본 Embedding만으로는 주변 문맥에 따른 의미 차이를 충분히 표현하기 어렵다
Self-Attention은 각 토큰이 다른 토큰과의 관계를 참고해 문맥이 반영된 새로운 벡터 표현을 만든다.
### Q2. Query-Key-Value의 차이는?
- Query는 현재 위치가 찾고 싶은 정보를 나타낸다.
- Key는 각 위치가 Query와 얼마나 관련 있는지 비교하는 기준이다.
- Value는 계산된 Weight에 따라 실제 Context에 섞이는 정보다. 
### Q3. Scaling이 필요한 이유는?
Query와 Key의 차원이 커질수록 Dot Product Score가 커질 수있다.
큰 Score는 Softmax를 지나치게 뾰족하게 만들어 Gradient를 불안정하게 할 수 있으므로 `√D` 로 나눠 크기를 조절한ㄷ.
### Q4. Softmax를 `dim=-1`에 적용하는 이유?
Score의 마지막 축이 Key 후보 축이기 때문이다.
각 Query가 모든 Key에 주는 참고 비율을 계산해야 하므로 Key 축에 Softmax를 적용한다.
### Q5. Context Vector는 어떻게 만들어지는가?
Attention Weight와 Value를 행렬 곱해 만든다.

`Context = Weight @ Value` 
여러 위치의 Value를 Weight에 따라 섞은 문맥 표현이다
### Q6. Mask를 Softmax 전에 적용하는 이유?
PAD 위치의 Score를 `-inf` 로 바꾸면 softmax 이후 해당 위치의 Weight가 0이 된다
Softmax 뒤에 Weight만 0으로 바꾸면 남은 Weight의 합이 1이 아니게 된다.
### Q7. Multi-Head_Attention에서 Head를 나누는 이유?
동일한 입력을 서로 다른 Projection 공간에서 처리해 여러 정류의 토큰 관계를 학습할 기회를 제공하기 위해서다.
### Q8. D_model=12, num_heads=3이면 D_head는 얼마인가? 

`D_head = 12 / 3 = 4` 
### Q9. Head별 Attention에서 Query와 Key의 길이가 같다면 다음과 같다.
`[B,H,L_query,L_key]`
### Q10. **MHA·MQA·GQA의 핵심 차이는?**
Query Head가 K/V Head를 공유하는 방식이 다르다. 
- MHA: Query Head마다 별도의 K/V
- MQA: 모든 Query Head가 하나의 K/V 공유

## 오늘의 한 줄 정리
> Self-Attention은 같은 입력에서 만든 Query-Key-Value로 토큰 간 관련도를 계산하고, Scaling-Mask-Softmax를 거진 Weight만큼 Value를 섞어 문맥 표현을 만든다.
