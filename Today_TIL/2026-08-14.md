## 💡 핵심 개념
- Accuracy → 불균형 데이터에서는 높아도 중요한 양성을 놓칠 수 있음
- Precision → 잡았다고 한 것 중 실제 양성이 얼마나 되는가
- Recall → 실제 양성 중 얼마나 찾아냈는가
- F1 → Precision과 Recall의 균형
- AP/ ROC-AUC → 여러 threshold에서 모델의 순위 성능 평가
- Threshold → 운영 비용에 맞춰 Validation에서 결정
- K- Fold → 여러 번 나눠 평가해 한 번의 분할에 따른 우연을 줄임
- Stratified → 클래스 비율 유지
- Group → 같은 문서·사용자·대화를 서로 다른 데이터에 섞지 않음
- TimeseriesSplit→ 과거에 학습하고 미래로 검증
- Data Leakage → 예측할 때 알 수 없는 정보가 학습에 들어가는 것
- Pipeline → 전처리 누수를 방

## ❓왜 필요한가?
1️⃣ 왜 Precision·Recall이 필요한가?
- 불균형 데이터에서는 Accuracy가 높아서 틀릴 수 있기 때문에 
2️⃣ 왜 Cross Validation이 필요한가?
- 한 번 데이터를 나눴을 때 우연히 좋은 데이터가 validation에 들어갈 수 있기 때문에
→ 여러 번 나눠서 평가하면 이 모델이 평균적으로 잘하는가 를 더 안정적으로 볼 수 있음
3️⃣ 왜 Stratified / Group이 필요한가?
- Stratified → 양성/음성 비율이 한쪽에 치우치지 않게
- Group → 같은 문서, 사용자가 Train과 Validation에 같이 들어가지 않게
- Timeseries → 미래 데이터를 미리 학습하지 않게
4️⃣ 왜 Pipeline이 필요한가?
- 전처리 과정에서 Validation 정보를 Train이 미리 보는 것을 막기 위기
⭐ 결국 4장 전체의 이유
- 모델 성능을 실제보다 좋게 착각하지 않기 위해서 
제대로 평가하지 않음
↓
성능이 좋아 보임
↓
실제 서비스에 배포
↓
생각보다 성능이 나쁨 
그래서 지표 → 데이터 분할 → 누수 방지 → 최종 Test 순서로 꼼꼼히 확인!
