## 1. 입력 분리

### 프롬프트, RAG, 파인튜닝의 차이

먼저 세 방법이 무엇을 바꾸는지 정리했다.

| 구분 | 바꾸는 대상 | 주요 용도 |
| --- | --- | --- |
| **프롬프트** | 모델에 전달하는 지시와 문맥 | 답변 규칙과 출력 형식 지정 |
| **RAG** | 검색해서 입력에 제공하는 근거 문서 | 변경되는 규정이나 지식 제공 |
| **파인튜닝** | 모델의 학습 가능한 가중치 | 반복되는 행동 실패 개선 |

**자주 바뀌는 규정은 문서로 제공하고, 지시해도 반복되는 행동 실패를 학습 목표로 삼는다는 점**이 중요했다.

예를 들어 숙박비 한도가 바뀌면 갱신한 문서를 제공할 수 있다. 반면 문서를 줘도 조건을 잘못 판단하거나, 정해진 JSON 형식을 반복해서 어기는 행동은 학습으로 개선할 대상이 된다.

### 모델 입력과 평가 기준 분리

모델에 줄 정보와 사람이 사용할 평가 기준은 분리해야 한다.

- **`cases`**: 모델에 전달할 질문과 근거 문서
- **`review_criteria`**: 사람이 확인할 정답 행동 기준

평가할 때 정답 기준까지 모델에 전달하면 **정답 누수**가 발생한다. 정답을 보여 준 상태의 결과로 모델의 원래 실력을 판단할 수는 없다.

근거가 없는 질문에 “지원 불가”라고 단정하는 것도 잘못이다. **확인할 수 없으면 답변을 보류하는 행동 자체가 학습 목표**가 될 수 있다.

### SFT, LoRA, QLoRA, DPO의 관계

| 방법 | 핵심 개념 |
| --- | --- |
| **SFT** | 모범답안의 토큰을 더 잘 예측하도록 학습 |
| **LoRA** | 기본 가중치를 고정하고 작은 추가 행렬을 학습 |
| **QLoRA** | 기본 가중치를 4비트로 저장하고 LoRA 부분을 학습해 메모리 사용을 줄임 |
| **DPO** | 선호 답변과 비선호 답변의 상대적 선호를 학습 |

SFT와 DPO는 **무엇을 학습 신호로 사용하는지**에 관한 구분이다. LoRA와 QLoRA는 **어떤 파라미터를 학습하고 메모리를 어떻게 사용하는지**에 관한 구분이다.

따라서 **“LoRA로 SFT를 한다”는 조합이 가능하다.**

## 2. 토큰과 학습 원리

### 모델이 텍스트를 처리하는 방식

모델은 텍스트를 그대로 읽는 대신 **토큰 ID로 변환된 입력**을 처리한다.

토큰은 글자나 단어와 정확히 일치하지 않는다. 같은 문장이라도 사용하는 토크나이저에 따라 나뉘는 방식과 토큰 수가 달라질 수 있다.

**채팅 템플릿**은 `system`, `user`, `assistant`의 역할 경계와 답변 시작 위치를 표시한다. 모델이 기대하는 형식에 맞게 입력을 구성하는 과정이다.

### 손실과 가중치 갱신

학습의 기본 흐름은 다음과 같다.

1. 모델이 다음 토큰 후보의 점수인 **로짓**을 계산한다.
2. softmax로 로짓을 확률로 변환한다.
3. 정답 토큰의 확률을 이용해 **손실**을 계산한다.
4. 학습 대상에 대한 손실의 **기울기**를 계산한다.
5. 옵티마이저가 학습 대상 값을 갱신한다.

**정답 토큰의 확률이 높아질수록 교차엔트로피 손실은 작아진다.**

기본적인 SGD 갱신식은 다음과 같다.

```text
새 값 = 기존 값 − 학습률 × 기울기
```

코드에서는 각 단계의 역할을 구분해야 한다.

| 코드 | 역할 |
| --- | --- |
| `optimizer.zero_grad()` | 이전에 누적된 기울기 초기화 |
| `loss.backward()` | 기울기 계산 |
| `optimizer.step()` | 학습 대상 값 갱신 |

### 주의할 점

- `cross_entropy`에는 **softmax를 적용하기 전 로짓**을 넣는다.
- 자료의 `p - y`는 **로짓에 대한 기울기**다. 실제 가중치의 기울기는 연쇄법칙으로 계산한다.
- 경사하강법은 기울기를 더하는 것이 아니라 **빼는 방향**으로 값을 갱신한다.
- **이번 장에서는 숫자 세 개로 학습 원리를 확인할 뿐, 실제 언어모델의 가중치는 바꾸지 않는다.**

## 3. 실제 응답 만들기

### 학습과 추론의 차이

실제 모델을 불러와 응답을 만드는 과정은 **추론**이다. 저장된 가중치를 사용해 답변을 생성하며, 이 과정에서 가중치를 갱신하지 않는다.

자료에서는 같은 네 문항에 기본 지시와 상세 지시를 적용해 **총 여덟 개의 응답**을 관찰한다.

상세 지시로 답변이 달라져도 그것은 **프롬프트 변경의 효과**다. 파인튜닝 효과로 해석하면 안 된다.

### 생성 조건 고정

학습 전후를 비교하려면 다음 조건을 맞춰야 한다.

- 모델 ID와 버전
- 질문과 근거 문서
- 실행 환경과 자료형
- 생성 설정

실습에서는 **greedy 생성**을 사용한다. 각 단계에서 가장 높은 점수의 토큰을 선택하는 방식이다.

추론에 사용하는 두 기능의 역할도 다르다.

| 기능 | 역할 |
| --- | --- |
| `model.eval()` | dropout 같은 모듈을 평가 동작으로 전환 |
| `torch.inference_mode()` | 기울기 계산을 위한 기록을 끔 |

### 주의할 점

이 실습의 `generate()` 결과에는 입력 토큰과 새로 생성한 토큰이 함께 포함된다. 따라서 **입력 길이 뒤의 토큰만 답변으로 읽어야 한다.**

응답이 깨졌을 때는 내용 문제로 판단하기 전에 **출력 토큰 제한 때문에 잘렸는지 먼저 확인**해야 한다. JSON을 생성하던 중 길이 상한에 도달하면 형식이 완성되지 않을 수 있다.

## 4. 나눠 읽기와 baseline

### 응답을 평가하는 세 가지 기준

마지막으로 응답 평가 기준을 정리했다.

| 기준 | 확인하는 내용 |
| --- | --- |
| **형식 통과** | JSON 파싱, 필드 구성, 상태 규칙, 인용 ID |
| **업무 의미** | 금액 비교, 승인 조건, 보류 이유의 정확성 |
| **참조 완전 일치** | 모범답안과 표현까지 같은지 |

**형식이 맞는 답변과 내용이 맞는 답변은 다르다.**

JSON 형식이 맞아도 승인 조건을 거꾸로 설명할 수 있다. 반대로 모범답안과 문장이 달라도 의미가 같으면 올바른 답일 수 있다.

인용한 문서 ID가 존재하는지 확인하는 것과, 그 문서가 답변을 실제로 뒷받침하는지 판단하는 것도 별개다.

### 자동 검사의 순서

자동 검사는 다음 순서로 진행한다.

1. **JSON 객체인지 확인한다.**
2. **필드와 상태 규칙을 확인한다.**
3. **인용 ID가 제공된 문서에 존재하는지 확인한다.**

이 실습의 출력 규칙에서는 답변 상태에 따라 인용 조건도 달라진다.

- **`answered`**: 근거를 바탕으로 답변하며, 인용이 있어야 한다.
- **`abstained`**: 답변을 보류하며, 인용은 비어 있어야 한다.

자료의 `simple 0/4`, `explicit 0/4`는 **관찰용 네 문항의 형식 검사 결과**다. 전체 업무 정답률이 0%라는 의미는 아니다.

### baseline.json의 역할

**baseline은 학습 전 모델의 실제 응답과 실패를 기록한 비교 기준**이다. 정답 모음이 아니므로 오답도 원본 그대로 남겨야 한다.

`baseline.json`에는 다음 정보를 함께 저장한다.

| 저장 항목 | 목적 |
| --- | --- |
| 모델 ID와 버전 | 같은 모델을 비교했는지 확인 |
| 입력과 평가 기준 | 같은 문제와 기준을 사용했는지 확인 |
| 실행 환경과 생성 설정 | 조건 차이가 있었는지 확인 |
| 원본 응답과 검사 결과 | 무엇을 틀렸고 어떻게 판정했는지 확인 |

이 정보를 함께 남겨야 나중에 결과가 달라진 이유를 추적할 수 있다.

Colab에서는 노트북 저장과 실행 중 생성한 파일의 보관이 별개다. **`baseline.json`은 따로 내려받아 보관해야 한다.**

## 오늘 배운 점

파인튜닝을 시작하기 전에 먼저 해야 할 일이 분명해졌다.

**모델이 근거를 잘못 읽는지, 형식을 어기는지, 근거 없이 답하는지를 구분하고, 그 실패를 학습으로 고칠 행동으로 정의해야 한다.**

이번 장에서 정리한 학습 목표는 다음과 같다.

- 근거 문서를 읽고 조건을 정확히 판단하기
- 정해진 JSON 형식으로 답하기
- 근거가 부족하면 답변을 보류하기
- 답변을 뒷받침하는 문서를 올바르게 인용하기
