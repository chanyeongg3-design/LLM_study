# DPO(Direct Preference Optimization), 직접 선호 최적화

- SFT(Supervised FineTuning, 지도 미세조정)는 모법답안을 따라 쓰도록 학습한다. DPO(Direct Preference Optimization, 직접 선호 최적화)는 같은 질문의 모범답안과 비선호 답변을 한쌍으로 비교한다.

- 학습 전 SFT 모델로 두 답변의 점수를 한 번 계산해 고정한다. 이후 같은 가중치에서 출발한 정책 모델을 갱신해 기준 대비 선호 점수 차이를 키운다.

- 학습에 쓴 답변쌍의 점수와 개발용 문항에서 직접 생성한 답변을 함께 본다. 전자는 선호 학습의 변화, 후자는 실제 답변 행동을 보여준다.

# 1. 핵심 개념

## 같은 질문에 붙인 두 답변이 학습 신호다.

질문이 "숙박비가 규정의 한도와 같으면 사전 승인이 필요한가?"라면, 모범답인인 `chosen`은 "한도와 같으므로 사전 승인이 필요하지 않습니다"라고 답한다. 교재용 `rejected`는 같은 조건을 초과로 판정해 승인이 필요하다고 답한다. 질문과 규정을 그대로 두면 모델에 어떤 판단을 더 선호해야 하는지 가르칠 수있다. 이 실습의 비선호 답변은 코드가 사례 유형에 따라 만든 것이며, `reason`은 사람이 쌍을 검토할 때 읽는 기록이다.

| 비교 항목       | SFT            | 이 노트북의 DPO                                |
| ----------- | -------------- | ----------------------------------------- |
| 한 문항에 주는 답변 | 모범답안 하나        | 모범답안과 교재용 오답                              |
| 학습 신호       | 모범답안의 다음 토큰 확률 | 고정 기준 대비 두 답변의 상대 점수 차이                   |
| 모델의 역할      | 모범답안을 예측하도록 갱신 | 학습 전 SFT에서 기준 점수를 뽑고, 같은 가중치에서 출발한 정책을 갱신 |
## 답변 점수는 어떻게 계산하나

토큰은 모델이 읽는 텍스트 조각이다. 모델은 앞의 토큰을 보고 다음 토큰이 나올 확률을 예측한다. 답변 전체의 조건부 확률은 각 토큰 확률을 곱한 값이라서, 로그를 취하면 각 토큰의 로그확률을 더해 구할 수있다. 코드는 질문과 규정을 문맥으로 읽고, **답변과 EOS(End of Sequence, 종료토큰)** 에만 점수를 매긴다.

- `input_ids`는 모델이 읽는 토큰 번호다. `attention_mask`의 0은 길이를 맞추기 위해 채운 패딩을 표시한다.
- `labels`의 `-100`은 점수 계산에서 건너뛸 위치다. 프롬프트와 패딩이 여기에 해당한다.
- `response_logps()`는 현재 위치의 예측과 다음 위치의 실제 토큰을 맞춰, 두 답변의 점수를 각각 합한다. 토큰당 평균은 답변별 합과 다른 값이다.

## 기준 점수와 현재 점수를 비교한다.

고정 기준인 reference는 학습 전 SFT가 매긴 점수다. policy는 현재 학습 중인 모델이다. 이 실습은 모드 선호쌍의 기준 점수를 미리 저장하므로 별도의 기준 모델을 GPU에 계속 올려 둘 필요가 없다.

```
margin = beta x (chosen의 변화량 - rejected의 변화량)
loss = -log(sigmoid(margin))
```

예시로 기준이 `[-4, -3]`, 현재가 `[-3, -4]`라면 chosen은 1점 오르고 rejected는 1점 내려간다.
`beta = 0.1`이므로 margin은 `0.1 x (1 - (-1)) = 0.2`다. 둘이 같은 모델에서 출발할 때 margin은 0이고 손실은 `ln(2) ≈ 0.6931`이다. 양의 margin은 기준보다 chosen 쪽으로 상대 점수가 이동했다는 뜻이다.
chosen 자체의 점수가 올랐는지는 `chosen_logp_before와 chosen_logp_after`를 보면 된다.

`BETA = 0.1`은 선호 차이에 곱하는 계수다. `LEARNING_RATE = 2e-5`는 AdamW가 가중치를 갱신할 때 쓰는 학습률이다. 이 실습은 `48쌍 x 2회 ÷ 4쌍 = 24회 ` 갱신하도록 작성됐다.

### ③ 점수 함수와 입력 변환·`dpo-toy`→ `encode-pairs`

```
`response_logps()`는 응답별 로그확률 합과 포함된 토큰 수를 반환한다. `dpo_terms()`는 이를 기준 점수와 비교해 손실, margin, 응답별 기준 대비 점수를 반환한다.
`encode_response()`가 채팅을 토큰으로 변환하고 점수 위치를 표시하면, `collate_pair()`가 길이를 맞춰 한 묶음에 담는다. `check_pair_batch()`가 묶음의 크기와 패딩 표시, EOS를 확인한다.
```


```python
# 모델의 토큰 점수와 정답 번호를 받아 응답별 로그확률 합과 점수에 포함된 토큰 수를 반환한다.
def response_logps(logits, labels):
	
	# logits:[B, T, V], labels:[B, T]. 위치 t가 t+1 토큰을 예측한다.
	# 한 칸 다음 위치가 예측 대상이고, -100인 대상은 응답 점수에서 제외한다.
	targets = labels[:, 1:]
	mask = targets.ne(-100)
	
	# 응답 위치만 골라 FP32 log-softmax와 같은 교차엔트로피 계산을 한다.
	token_logps = -F.cross_entropy(
		logits[:, :-1, :][mask].float(),
		targets[mask],
		reduction="none",
	)
	
	# 선택한 토큰이 어느 응답에 속했는지 이용해 두 응답의 로그확률을 따로 합한다.
	# 각 토큰의 배치 행 번호를 얻어 chosen과 rejected의 점수를 따로 더한다.
	owners = mask.nonzero(as_tuple=False)[:, 0]
	sums = torch.zeros(
		logits.shape[0], device=logits.device
	).scatter_add(0,owners, token_logps)
	return sums, mask.sum(dim=1)
```

```python
# 기능 | 정책과 기준의 chosen·rejected 점수를 비교해 DPO 손실, 상대 선호 변화량, 응답별 기준 대비 점수를 반환합니다.
def dpo_terms(policy_logps, reference_logps):

    # 한 쌍은 chosen, rejected 순서입니다. reference에는 기울기를 흘리지 않습니다.
    # 현재 정책의 점수에서 고정 기준의 점수를 빼 변화량을 비교합니다.
    log_ratios = policy_logps - reference_logps.detach()
    # 응답마다 정책과 기준의 점수 차이에 beta를 곱합니다.
    
    rewards = BETA * log_ratios
    # chosen의 변화량에서 rejected의 변화량을 뺍니다.
    
    margin = rewards[0] - rewards[1]

    # log-sigmoid를 직접 사용해 작은 확률에서도 계산을 안정적으로 유지합니다.
    return -F.logsigmoid(margin), margin, rewards
```

### ⑤ 정책 갱신 · `train-dpo`

매 쌍마다 현재 모델 점수와 해당 쌍의 기준 점수로 손실을 계산한다. 기울기는 손실을 줄이려면 가중치를 어느 방향으로 얼마나 바꿔야 하는지 알려주는 값이다. 네 쌍의 기울기를 누적한 뒤 크기를 제한하고 AdamW로 한 번 갱신한다. 학습 후에는 기준 점수가 그대로인지, 선택한 가중치 원소에 변화가 있는지도 확인한다.

```python
        # 현재 정책의 두 점수를 다시 계산해 같은 쌍의 고정 기준 점수와 비교합니다.
        scores = pair_logps(model, pairs[index])
        loss, margin, rewards = dpo_terms(
            scores, reference_scores[index].to(model.device)
        )
        if not torch.isfinite(loss):
            raise FloatingPointError("DPO loss가 유한하지 않습니다.")

        # 한 쌍 안에서는 토큰 log-prob를 합하고, 네 쌍의 손실은 평균해 한 번 갱신합니다.
        (loss / ACCUMULATION).backward()
```

# 3. 내 RAG 프로젝트에 적용

적용할 곳은 해운 규정 RAG(Retrieval-Augmented Generation, 검색 증강 생성)에서 검색된 근거를 읽고 답변하는 단계다.

1. 같은 질문과 검색 문서를 고정하고, 규정에 맞는 답변 chosen으로 작성한다. 한도 경계를 틀리거나, 근거가 없는데 단정하거나, 무관한 문서를 인용하는 답변을 유형별 rejected로 만든다.

2. 규정 그룹 단위로 학습과 개발 문항을 나눈다. 개발 문항에서는 전후 모델에 같은 검색 결과와 생성 설정을 주고 별도 정답 없이 생성한 원문을 비교한다.

3. 개발 결과는 **근거가 충분한데 보류한 건수**, **근거가 부족한데 답한 건수**, **인용 규정이 결론을 뒷받침한 건수**를 각 유형의 전체 건수와 함께 기록한다. 검색 단계의 품질은 같은 평가 문항에서 Recall@k (관련문서가 상위 k개 검색 결과에 들어온 비율)로 따로 확인한다.
