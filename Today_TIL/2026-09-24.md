## 2. 핵심 개념 정리

### 1) Timeout

**정의**

외부 API가 너무 오래 응답하지 않을 때 **기다리는 시간을 제한하는 기능**이다.

```
async with httpx.AsyncClient(timeout=2.0) as client:
    response = await client.post(
        api_url,
        json={"prompt": prompt},
    )
```

**왜 필요한가?**

외부 LLM API가 멈추거나 느려졌는데 계속 기다리면 우리 FastAPI 서버도 요청을 끝내지 못한다.

```
외부 LLM 응답 지연
        ↓
우리 서버도 계속 대기
        ↓
사용자도 계속 기다림
```

Timeout을 설정하면 일정 시간이 지나면 실패로 처리할 수 있다.

> **Timeout = “언제까지 기다릴지 정하는 것”**

---

### 2) Retry

**정의**

일시적인 오류가 발생했을 때 **요청을 다시 시도하는 것**이다.

이번 실습에서는:

|오류|Retry|
|---|---|
|Timeout|O|
|5xx|O|
|400|X|
|401 / 403|X|
|404|X|
|429|즉시 Retry하지 않음|

예:

```
for attempt in range(2):
    try:
        response = await client.post(
            api_url,
            json={"prompt": prompt},
        )

    except httpx.TimeoutException:
        if attempt == 0:
            await asyncio.sleep(0.01)
            continue

        raise ExternalServiceError(
            "외부 API 응답 시간이 초과되었습니다."
        )
```

`range(2)`이므로:

```
첫 번째 호출
     ↓
    실패
     ↓
한 번 재시도
```

즉,

- **최대 호출 = 2번**
    
- **Retry = 최대 1번**
    

이다.

> **Retry = “일시적인 문제라면 한 번 더 해보기”**

---

### 3) 외부 API 오류 처리

외부 LLM/API 호출에서는 여러 종류의 오류가 발생할 수 있다.

예:

```
Timeout
네트워크 연결 실패
5xx
4xx
잘못된 JSON
answer가 없는 응답
```

이런 외부 서비스 오류를 하나의 예외로 묶을 수 있다.

```
class ExternalServiceError(RuntimeError):
    """외부 API 실패를 표현합니다."""
```

그리고 FastAPI에서는:

```
try:
    answer = await call_with_one_retry(
        client,
        api_url,
        prompt,
    )

except ExternalServiceError as error:
    raise HTTPException(
        status_code=502,
        detail=str(error),
    )
```

처럼 처리한다.

### 주요 상태 코드

|상태 코드|의미|
|---|---|
|**422**|사용자가 보낸 요청 데이터 문제|
|**502**|외부 LLM/API에서 정상 답을 받지 못함|
|**429**|너무 많은 요청으로 호출 제한|

### 왜 502인가?

우리 FastAPI 서버 자체가 고장 난 것이 아니라,

```
사용자
  ↓
우리 FastAPI
  ↓
외부 LLM ❌
```

처럼 **뒤쪽 외부 서비스에서 정상 응답을 받지 못했기 때문**이다.

> **502 = “뒤에 있는 외부 서버에서 정상 답을 못 받음”**

### 4) Middleware와 요청 로그

**Middleware**는 API 요청이 들어오고 나가는 과정에서 **공통 작업을 처리하는 기능**이다.

이번에는:

- HTTP Method
    
- Path
    
- Status Code
    

만 기록한다.

```
@app.middleware("http")
async def request_log_middleware(
    request: Request,
    call_next,
):
    # 실제 Endpoint 실행
    response = await call_next(request)

    # 요청 결과 기록
    make_request_log(
        request.method,
        request.url.path,
        response.status_code,
    )

    return response
```

로그 예:

```
POST /query -> 200
POST /query -> 502
```

### 왜 필요한가?

서비스에 문제가 생겼을 때:

```
어떤 요청?
   ↓
어떤 API?
   ↓
결과 상태 코드는?
```

을 확인할 수 있다.

### 로그에 남기면 안 되는 것

- 전체 `question`
    
- 전체 `context`
    
- API Key
    
- `Authorization` Header
    

비밀값이나 개인정보가 포함될 수 있기 때문이다.

> **Middleware = “API 앞뒤의 공통 처리 담당”**

## 3. 전체 구조에서의 위치

|단계|구성 요소|역할|
|---|---|---|
|1|사용자|질문 전송|
|2|FastAPI|`/query` 요청 수신|
|3|Pydantic|입력 검증|
|4|Prompt|질문 + 근거 구성|
|5|AsyncClient|외부 LLM API 호출|
|6|Timeout|너무 긴 대기 차단|
|7|Retry|일시적 실패 다시 시도|
|8|Error Handling|외부 오류를 502로 변환|
|9|Middleware|요청 결과 로그|
|10|사용자|답변 또는 오류 수신|

```
[사용자]
   ↓
[FastAPI /query]
   ↓
[Pydantic 검증]
   ↓
[Prompt 생성]
   ↓
[외부 LLM API]
   ↓
┌─────────────────────┐
│ Timeout             │
│ Retry               │
│ Error Handling      │
└─────────┬───────────┘
          ↓
     [LLM Answer]
          ↓
    [QueryResponse]
          ↓
       [사용자]

Middleware
→ Method / Path / Status 기록
```

## 4. Retry 판단 기준

|상황|재시도|이유|
|---|---|---|
|Timeout|O|일시적인 지연일 수 있음|
|500 / 503|O|서버의 일시적 오류일 수 있음|
|400|X|요청 자체가 잘못됨|
|401 / 403|X|인증·권한 문제|
|404|X|주소 또는 자원 문제|
|429|바로 하지 않음|호출 제한 정책 확인 필요|

특히:

```
429
 ↓
Too Many Requests
 ↓
Rate Limit
```

즉 **서버 장애가 아니라 호출량 제한**일 수 있다.

## 5. 실제 LLM 프로젝트에서는 어떻게 사용되는가?

LLM API는 일반 API와 마찬가지로 외부 서비스이므로:

- 응답이 느려질 수 있고
    
- 네트워크 오류가 발생할 수 있고
    
- Rate Limit이 발생할 수 있고
    
- 서버 오류가 발생할 수 있다.
    

따라서:

```
사용자 질문
    ↓
FastAPI
    ↓
Prompt 생성
    ↓
LLM API 호출
    ↓
Timeout
    ↓
오류 판단
    ↓
필요하면 Retry
    ↓
성공 → 답변 반환
실패 → 오류 반환
```

구조를 만들어야 한다.

즉 이번 강의는 단순히:

> **“LLM을 호출하는 방법”**

이 아니라,

> **“LLM 호출이 실패하더라도 서비스가 안정적으로 동작하게 만드는 방법”**

을 학습한 것이다.

## 6. 같이 알아두면 좋은 개념

**5xx**  
→ 외부 서버 측 문제

**4xx**  
→ 요청·인증·권한 등의 문제

**429**  
→ 너무 많은 API 요청

**Rate Limit**  
→ API 호출량 제한

**Retry-After**  
→ 서버가 알려주는 재시도 대기 시간

**Exponential Backoff**  
→ 실패할수록 Retry 간격을 증가

**Jitter**  
→ 여러 요청의 Retry 시점을 분산

**Middleware**  
→ 여러 Endpoint에 공통 기능 적용

**Logging**  
→ 서비스 실행 상태 기록

## 7. 복습용 핵심 정리

**Timeout**  
→ 외부 API를 무한정 기다리지 않음  
→ **“기다림 마감시간”**

**Retry**  
→ 일시적인 오류를 다시 시도  
→ **“한 번 더 해보기”**

**ExternalServiceError**  
→ 외부 API 오류를 하나로 묶음  
→ **“외부 서비스 문제 표시”**

**502**  
→ 외부 서비스에서 정상 응답을 얻지 못함  
→ **“뒤쪽 서버 문제”**

**429**  
→ 너무 많은 요청  
→ **“API 호출 제한”**

**Middleware**  
→ 요청 전후 공통 작업  
→ **“API 앞뒤 공통 처리”**
