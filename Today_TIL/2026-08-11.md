## 머신러닝 심화 for LLM - 1강 1장 

### 1. 지도학습과 비지도학습
지도학습(supervised Learning)
정답(레이블)이 있는 데이터로 학습하는 방식이고, 입력(X)와 정답(y)의 관계를 배워서, 새로운 입력이 들어왔을 때 정답을 예측합니다
ex) 집의 면적·위치 데이터(X)와 실제 거래 가격(y)을 함께 주고, 가격을 맞히도록 학습 시키는 것이 지도학습입니다
비지도 학습(Unsupervised Learning)
정답이 없는 데이터에서 숨어 있는 구조나 패턴을 스스로 찾는 방식이고, 정답을 맞히는 것이 아니라, 데이터를 비슷한 것 끼리 묶거나(군집화) 더 간단하게 요약(차원축소)합니다
ex) 고객 데이터를 비숫한 구매 성향끼리 자동으로 묶는 작업은 정답 레이블 없이 진행되는 비지도학습입니다.
## 정답이 있는지 없는지가 그렇게 중요한 기준인가?
아주 중요!! 정답(y)의 유무가 사용할 수 있는 알고리즘과 평가 방법을 완전히 갈라 놓기 때문
정답이 있으면 예측이 얼마나 맞았는지 직접 채점할 수 있지만, 정답이 없으면 채점 기준 자체가 달라집니다.
그래서 문제를 만나면 ‘정답 데이터가 있는가’ 를 먼저 확인하는 습관이 필요합니다. 
## 2. 문제 유형: 회귀·분류·군집화·차원축소
### 네 가지 대표 문제 유형
머신러닝 문제는 크게 지도학습의 회귀·분류, 비지도학습의 군집화·차원축소로 나눌수 있습니다.
어떤 유형인지에 따라 모델도, 평가지표도 완전히 달라집니다

## 3. 데이터 분리: train / valid / test split
### 왜 데이터를 나눌까?
모델이 학습에 쓴 데이터로 자기 성능을 평가하면, 답을 미리 보고 시험을 치는 것과 같습니다.
실제로는 처음 보는 데이터에서 잘 작동해야 하므로, 학습에 쓰지 않은 데이터로 성능을 확인해야 합니다.
그래서 데이터를 학습용·검증용·테스트용 나눠서, 모델이 처음 보는 데이터에 얼마나 잘 일반화 되는지를 정직하게 측정합니다. 
### 세 데이터 세트의 역할 
- 학습:(train): 모델이 패턴을 학습하는 데 사용
- 검증(validation): 하이퍼파라미터 튜닝과 모델 선택에 사용
- 테스트(test): 최종 성능을 딱 한 번 확인하는데 사용
> (Notion 이미지: ml_v12_1_1_1.png)
- 데이터 누수 
- 여러 행을 갖는 것도 주의해야함
- stratify는 분류 문제에서 클래스 비율을 유지하기 위한 설정입니다.
회귀에서는 제거합니다.
또 같은 문서에서 나온 여러 chunk, 같은 사용자 대화처럼 서로 강하게 연결된 샘플은 행 단위로 무작위 분리하면 안됩니다.
이 경우에는 그룹 단위로 나누고, 시간에 따라 예측하는 문제라면 과거로 학습해 미래를 검증해야 합니다.
### 검증 세트와 테스트 세트는 모두 학습에 쓰지 않는데, 굳이 나눌 필요가 있을까?
역할이 달라서 나눠야 합니다. 검증 세트는 여러 모델과 설정 중에 무엇이 좋은지 고르는데 반복적으로 사용됩니다.
그 과정에서 검증 세트에는 이미 우리의 선택이 스며듭니다. 그래서 진짜 처음 보는 데이터에서의 성능을 알려면, 한 번도 건드리지 않은 테스트 세트가 별도로 필요합니다. 
### 심화: 데이터가 적을 때는 교차 검증(Cross-Validation)
데이터가 적으면 검증 세트를 따로 떼는 것 만으로도 학습 데이터가 크게 줄어 아쉬운데, 이럴 때는 K- 겹 교차검증을 사용해 데이터를 여러 번 나눠 돌아가며 검증하면, 적은 데이터로도 안정적인 성능 추정을 얻을 수 있습니다.
## 4. 회귀 평가지표
### 회귀는 “얼마나 빗나갔는가” 로 평가합니다
회귀는 연속적인 숫자를 예측하므로, 예측값과 실제값의 차이(오차)를 기준으로 성능을 측정합니다.
오차가 작을수록 좋은 모델입니다.

## 5. 분류 평가지표

## ★ 핵심
### 지도학습 
숫자를 예측 → 회귀
종류를 예측 → 분류
### 비지도학습
컴퓨터가 데이터를 살펴보고 서로 비슷하면 스스로 그룹을 만듬 → 군집화
지도학습 → 정답있음
비지도학습 → 정답없음
### Train
문제 → 답 확인 → 공부
모델이 실제로 여기서 학습한다.
### Validation
여러 모델을 만들어보고 어떤 모델이 좋은지 선택한다.
모델 A → 80점
모델 B → 90점
모델 C → 85점
### Test
마지막에 “그래서 이 모델이 처음 보는 문제도 잘 풀 수 있나? “를 확인한다
### 왜 Validation과 Test를 따로 만들까?
만약 Test 문제를 계속 보면서 모델을 수정하면
시험 문제를 계속 봄
↓
시험 문제에 맞춰 공부
↓
시험 점수 ↑
하지만 실제 실력이 좋아진 것은 아니다. 
그래서 Validation = 모델을 고르는 데 사용, Test = 마지막 성적 확인으로 분리한다.
Baseline이 중요한 이유
내가 엄청난 머신러닝 모델을 만들었는데 결과가 정확도 90% 라고 나왔어
과연 좋은 모델일까? 아직 몰라
왜냐면 아무것도 안하는 단순한 방법이 95%일 수도 있기 때문이야
그래서 먼저 기준 모델인 Baseline을 만든다.
머신러닝에서는 단순한 기준 모델보다 정말 더 잘하고 있는가? 를 확인하는 것이 중요하다
### 회귀 평가지표
회귀는 숫자를 예측하기 때문에 “얼마나 틀렸는가?를  측정한다
오차를 어떻게 계산하느냐에 따라 여러 지표가 나온다
### MAE - 평균적으로 얼마나 틀렸어?
아주 직관적이다
### RMSE - 큰 실수를 더 싫어
RMSE는 MAE와 비슷하지만 큰 오차를 더 강하게 벌준다.
### R² — 이게 가장 헷갈릴 수 있음
R²는 단순히 “오차가 몇이냐”를 보는 지표가 아니다
쉽게 말해 “이 모델이 데이터를 얼마나 잘 설명하고 있냐? 를 보는 지표
R² = 1 → 모델이 데이터를 아주 잘 설명, 잘 설명할 수록 R²가 1에 가까움
R² = 0
여기서 중요한 기준이 등장한다.
> **평균값만 예측하는 단순한 모델**
과 비슷한 수준이라는 뜻이다.
### Precision = 내가 잡은 것의 정확성
Recall = 진짜 양성을 얼마나 놓치지 않았나
### Precision과 Recall을 왜 같이 볼까?
둘은 서로 반대 방향으로 움직이는 경우가 많다.
그래서 둘 중 하나만 보면 안된다.
### F1 Score
Precision과 Recall을 함께 고려하는 점수 
둘 다 높여야 F1도 높게 나온다.
F1 = Precision과 Recall의 균형 점
### ROC-AUC와 AP는 뭐야?
여기는 처음부터 복잡하게 외울 필요 없다.
둘 다 기본적으로
> **모델이 양성과 음성을 얼마나 잘 구분해서 순위를 매기는가**
를 보는 지표라고 이해하면 된다.
이런 순위 성능을 평가하는데 ROC-AUC나 AP가 사용된다.
## 전체를 연갈하면 
① 데이터 준비
↓
② Train / Valid / Test 분리
↓
③ Train으로 모델 공부
↓
④ Validation으로 좋은 모델 선택
↓
⑤ Test로 최종 시험
↓
⑥ 평가지표로 성능 확인
그리고 문제에 따라 지표가 달라진다.
```Plain Text
            문제
             │
    ┌────────┴────────┐
    ↓                 ↓
   회귀              분류
 숫자 예측          종류 예측
    │                 │
```
┌────┼────┐       ┌────┼─────┐
↓    ↓    ↓       ↓    ↓     ↓
MAE RMSE  R²    Accuracy Precision Recall
│       │
└───┬───┘
↓
F1
