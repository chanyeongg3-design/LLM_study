## 📚 오늘 배운 것:
Hugging Face를 이용한 텍스트 분류 Fine-tuning의 전체 과정을 배웠다. 
- 7-1강: 분류 문제 정의와 데이터 품질 점검
- 7-2강: DatasetDict, 라벨 인코딩, 데이터 분할 고정
- 7-3강: Tokenization Mapping과 Data Collator
- 7-4강: Sequence Lassification 모델과 라벨 매핑
- 7-5강: compute_metrics와 Accuracy, Macro-F1
- 7-6강:  TrainingArguments와 Trainer 구성
- 7-7강: Fine-tuning 실행, 평가, Checkpoint 관리
- 7-8강: 오류 분석과 Fine-tuning
```Plain Text
전체 흐름
→ 라벨 매핑, 데이터 분할
→ 토큰화, 배치 구성
→ 분류 모델 구성
→ 평가 함수, 학습 설정
→ Fine-tuning
→ 최종 평가 및 저장
→ 오류 분석 및 리포트
```
> Fine-tuning은 모델을 학습시키는 것뿐 아니라 데이터와 평가 기준을 설계하고, 결과를 재현 및 설명할 수 있도록 기록하는 과정이다. 
## 💡 핵심 개념:
### 1. 문제 정의와 데이터 품질 — 7-1강
학습 전에 **입력·출력·라벨 규칙·성공 기준·실패 리스크**를 정한다.
데이터에서는 결측, 빈 문자열, 라벨 불균형, 데이터 누수 후보를 확인한다. 특히 같은 문장이 train과 test가 들어가거나 실제 예측 시 사용할 수없는 정답 정보가 포함되면 평가 성능이 부풀려질 수 있다.
라벨명이 원문에 자연스럽게 등장하는 것은 정상적인 단서일 수 있으므로, 그것만으로 누수라고 판단하지 않는다.
### 2. DatasetDic와 라벨 패밍**·분할 — 7-2강**
DatasetDict는 split 이름 별로 Dataset을 담는 구조다. 

- label2id: 라벨 이름  → 정수 ID
- id2label: 정수 ID → 라벨 이름
- Seed: 같은 조건에서 분할을 재현하도록 도움
- Stratify: 라벨 비율을 가능한 한 유지하며 분할
> 원래 train을 약 90:10 으로 나누어 train**·**validation 으로 사용하고, 원래 validation 을 test 역할로 사용한다. 
### 3. Tokenizer와 Data Collator — 7-3강

Truncation은 긴 입력을 자르고, padding은 짧은 입력의 길이를 맞춘다. 
**Dynamic padding은 현재 배치의 가장 긴 입력에 맞추므로 불필요한 패딩을 줄일 수 있다.** 
> map(batched=True)의 전처리 묶음은 실제 학습 batch size와 별개다. 
### 4. 분류 모델**·Logits·Loss — 7-4강**
분류 모델은 Base Model의 문맥 표현을 Classification Head를 통해 클래스별 점수로 바꾼다.

B는 샘플 수, L은 입력 길이, C는 클래스 수다
Lobels를 전달하면 loss가 계산된다. 하지만 계산만으로 학습되는 것은 아니며 backward와 optimizer 업데이트가 필요하다.
> 이번 단일 라벨 분류의 CrossEntropyLoss에는 softmax 이전 logits를 사용한다.
### 5. 평가 지표와 compute_metrics — 7-5강

배송 90개·환불 10개를 모두 배송으로 예측하면 Accuracy는 90% 지만 환불 Recall은 0%다.
따라서 **불균형 데이터에서는 Macro-F1과 클래스별 성능도 확인해야 한다.** 
> compute_metrics는 logits에서 argmax로 예측 ID를 선택하고, 정답과 비교해 지표 딕셔너리를 반환한다.
### 6. TrainingArguments와 Trainer — 7-6강
- TrainingArguments: epoch, batch_size, learning rate, 평가·저장 주기 등 설정
- Trainer: 모델·데이터·Collator·평가 함수를 연결해 실행
metric_for_best_model= “macro-f1”은 검증 Macro-F1로 모델로 선택한다는 뜻이다.
load_best_model_at_end=True이면 학습 종료 후 최상 모델을 로드한다. 
이 기능은 학습을 일찍 멈추는 Early stopping과는 다르다. 
### 7. Fine-tuning과 저장 — 7-7강
`Forward → Loss → Backward → Optimizer step` 

Final model은 반드시 마지막 epoch의 모델이 아니다. 모델과 Tokenizer를 함께 저장하고, 실행 설정·라벨 매핑·평가 결과도 기록한다. 
### 8. Error Analysis와 리포트 — 7-8강
원문·정답·예측·Confidence·정답 여부를 함께 저장한다.
클래스별 지표로 약한 라벨을 찾고, 혼동 행렬과 원문으로 반복 오류를 확인한다. 
혼동 행렬은 **행이 실제 라벨, 열이 예측 라벨이다.** 
Confidence는 선택한 클래스의 softmax 점수이며 실제 정답을 보장하지 않는다.
리포트에는 설정과 점수뿐 아니라 오류 패턴· 가능한 원인· 개선안· 검증 계획까지 작성한다. 
## 🛠️ 핵심코드: 
### 1. 데이터 로드·라벨 매핑·분할 — (7-1~7-2)
KULE YNAT 뉴스 분류 데이터셋을 불러온 뒤, train/validation/test로 나누는 전처리 준비 코드 
```Python
# Hugging face datasets 라이브러리에서
# 데이터셋을 불러오는 함수와 DatasetDict 클래스를 가져옴
from datasets import load_dataset, DatasetDict
# 데이터 분할 결과를 매번 동일하게 만들기 위한 랜덤 시드
SEED = 42
# 나중에 사용할 사전학습 한국어 RoBERTa 모델
MODEL_ID = "klue/roberta-small"
# Hugging face에서 KLUE 데이터셋의 YNAT 태스크를 불러옴
# YNAT: 뉴스 제목을 보고 어떤 분야의 뉴스인지 분류하는 데이터셋 
raw_ds = load_dataset("klue/klue", "ynat")

# 실제 컬럼과 샘플 확인
# train, validation 등이 어떻게 구성되어 있는지 확인
print(raw_ds)
# train 데이터의 첫 번째 샘플 확인
print(raw_ds["train"][0])

# 데이터 셋 자체에 저장되어 있는 label 이름들을 가져옴
# 각각의 숫자가 실제로 어떤 카테고리를 의미하는지 확인하기 위함 
label_names = raw_ds["train"].features["label"].names

# Label ID -> Label 이름 
idlabel = dict(enumerate(label_names))

# Label 이름 -> Label ID
# 모델 설정에서 label 이름과 숫자를 연결할 때 사용
label2id = {name: idx for idx, name in id2label.items()}

# 원래 train 데이터의 90%(새로운 train), 10%(새로운 validation)
# test_size=0.1 -> 전체의 10%를 test라는 이름으로 분리
# 여기서 만들어지는 test는 최종 test가 아니라 validation용 데이터임
split_ds = raw_ds["train"],train_test_split(
		test_size=0.1, # 10% 분리
		seed=SEED, # 매번 동일한 데이터가 나눠도록 설정
	  # label 비율을 최대한 유지하면서 분할
	  # train/validation에서도 비슷한 비율이 유지되도록 함 
		stratify_by_column = "label", 
)

dataset = DatasetDict({
		# 기존 train 데이터의 90% -> 실제 모델 학습에 사용 
		"train": split_ds["train"],
		# 기존의 train 데이터의 10% -> 학습 중 성능 확인에 사용
		"validation": split_ds["test"],
		# 원래 KLUE에서 validation으로 제공된 데이터 -> 여기서는 최종 test 데이터로 사용 
		"test": raw_ds["validation"],
})
```
> 이 코드의 핵심 목적은: 
> 1. 데이터 불러오기 → 2. 라벨 정보 준비 → 3. 기존 Train을 9:1로 분리 → Train/Validation/Test 구성
### 2. 토큰화**·배치 구성·모델 생성 — 7-3~7-4강**
train/validation/test 데이터셋을 RoBERTa 모델이 실제로 받을 수 있는 형태로 변환하고, 뉴스 분류 모델까지 불러오는 과정이다. 
```Python
# 필요한 Transformer 도구 불러오기 
from transformers import (
		# MODEL_ID를 보고 해당 모델에 맞는 Tokenizer을 자동으로 불러옴 
    AutoTokenizer,
    # 사전학습 모델 + 문장 분류용 Classification  Head를 불러옴 
    AutoModelForSequenceClassification,
    # Batch를 만들 때 문장 길이에 맞춰 동적으로 Padding
    DataCollatorWithPadding,
)
# 앞에서 설정한 MODEL_ID = "klue/roberta-small"
# 해당 모델과 호환되는 Tokenizer를 불러옴 
tokenizer = AutoTokenizer.from_pretrained(MODEL_ID)

def tokenize_batch(examples):
		# 뉴스 제목을 모델이 이해할 수 있는 Token ID 형태로 변환 
    result = tokenizer(
        examples["title"], # YNAT에서 실제 입력으로 사용할 뉴스 제목 
        truncation=True, # max_length를 넘어가는 문장을 잘라냄
        max_length=64, # 최대 Token 길이를 64로 제한
    )
    # 원래 데이터의 정답 label을 모델이 사용하는 labels라는 이름으로 저장
    # Hugging face 분류 모델은 labels가 전달되면 자동으로 loss까지 계산 
    result["labels"] = examples["label"]
    return result

tokenized_dataset = dataset.map(
    # 각 데이터에 적용할 함수
    tokenize_batch,
    # 하나씩 처리하지 않고 여러 샘플을 Batch 단위로 처리
    # -> Tokenization 속도가 빨라짐
    batched=True,
    # Tokenization이 끝난 후 기존 컬럼 제거,
    # 최종적으로 모델 학습에 필요한 input_ids, attention_mask, labels 등을 남김 
    remove_columns=dataset["train"].column_names,
)

data_collator = DataCollatorWithPadding(
    # 어떤 Tokenizer의 padding 규칙을 사용할지 지정
    tokenizer=tokenizer,
    # 최종 Batch를 PyTorch Tensor 형태로 반환 
    return_tensors="pt",
)

model = AutoModelForSequenceClassification.from_pretrained(
    # 사전학습된 KLUE RoBERTa Small 모델 사용 
    MODEL_ID,
    # 분류해야하는 클래스 개수 
    num_labels=len(label_names),
    # 숫자 ID -> 실제 Label 이름 
    id2label=id2label,
    # 실제 Label 이름 -> 숫자 ID
    label2id=label2id,
)
```
특히 기억해야 할건 Tokenizer → DataCollator → Model의 역할 차이
> Tokenizer는 문장을 Token ID로 변환하고, DataCollator는 여러 샘플을 하나의 Batch로 묶으면서 길이를 맞추고, Model은 그 Batch를 받아 실제 뉴스 카테고리를 예측한다. 
### 3. 평가 함수 작성 — 7-5강
모델의 예측 결과인 logits를 실제 클래스 번호로 바꾼 뒤, Accuracy와 Macro F1을 계산하는 함수
```Python
import numpy as np
from sklearn.metrics import accuracy_score, f1_score

def compute_metrics(eval_pred):
		# 모델의 예측값(logits)과 실제 정답(labels)을 분리
    logits, labels = eval_pred

    # 일부 모델은 logits을 tuple 형태로 반환할 수 있으므로 
    # 실제 logits만 꺼냄 
    if isinstance(logits, tuple):
        logits = logits[0]
		# 각 샘플에서 가장 높은 logit의 클래스 번호를 선택
		# [B, num_labels] -> [B]
    preds = np.argmax(logits, axis=-1)
		
		# 실제 정답(labels)와 예측값(preds)을 비교하여 평가 
    return {
        # 전체 예측 중 맞힌 비율 
        "accuracy": accuracy_score(labels, preds),
        # 각 클래스를 동일한 비중으로 F1 계산 후 평균 
        "macro_f1": f1_score(
            labels,
            preds,
            # 평가할 전체 클래스 ID
            labels=list(range(len(label_names))),
            # 클래스별 F1을 계산한 뒤 동일하게 평균
            average="macro",
            # 계산할 수 없는 경우 0으로 처리 
            zero_division=0,
        ),
    }
```
한 줄 정리: `compute_metrics()` = 모델의 logits → 클래스 예측값으로 변환 → 정답과 비교 → Accuracy와 Macro F1 계산 
여기서는 평가할 클래스 목록을 명시해 같은 클래스 집합을 기준으로 Macro-F1을 계산 
### 4. Trainer 설정**·학습·저장 — 7-6~7-7강**
학습 조건 설정 → Trainer 구성 → 학습 → 검증 → 모델 저장 순서로 실행된다
```Python
# 학습 조건을 설정하는 TrainingArguments와
# 학습·평가·저장을 실행하는 Trainer를 불러온다.
from transformers import TrainingArguments, Trainer


# ============================================================
# 1. 학습 조건 설정
# ============================================================
# 여기서는 eval_strategy와 processing_class를 지원하는
# Transformers 설치 환경을 가정한다.
#
# SEED, model, tokenized_dataset, data_collator,
# compute_metrics, tokenizer는 앞에서 만들어져 있어야 한다.

training_args = TrainingArguments(
    # 학습 중 checkpoint를 저장할 폴더
    output_dir="artifacts/ynat/checkpoints",

    # 전체 학습 데이터를 2번 순회한다.
    num_train_epochs=2,

    # 장치 하나당 한 번에 처리할 학습 샘플 수
    # GPU 메모리가 부족하면 이 값을 줄이는 방법을 고려한다.
    per_device_train_batch_size=16,

    # 장치 하나당 한 번에 처리할 평가 샘플 수
    # 평가에서는 역전파를 하지 않아 학습보다 크게 설정할 여지가 있다.
    per_device_eval_batch_size=32,

    # 학습률: 2 × 10^-5 = 0.00002
    # 파라미터를 업데이트하는 크기에 영향을 준다.
    # 실제 학습 중 값은 learning-rate scheduler에 따라 달라질 수 있다.
    learning_rate=2e-5,

    # 가중치 크기를 억제하는 정규화 설정
    # 과적합을 완화하는 데 도움이 될 수 있다.
    weight_decay=0.01,

    # 매 epoch가 끝날 때 validation 데이터로 평가한다.
    eval_strategy="epoch",

    # 매 epoch가 끝날 때 checkpoint를 저장한다.
    # 여기서는 평가와 저장 시점을 동일하게 맞춘다.
    save_strategy="epoch",

    # 기본 steps 방식의 logging에서
    # optimizer 업데이트 50 step마다 학습 로그를 기록한다.
    # 이 설정이 평가나 checkpoint 저장 주기를 뜻하는 것은 아니다.
    logging_steps=50,

    # checkpoint 보관 수를 제한해 저장 공간을 관리한다.
    # best checkpoint 보존 정책과 함께 적용된다.
    save_total_limit=2,

    # 학습 종료 후 검증 지표가 가장 좋았던 모델을 다시 불러온다.
    # 마지막 epoch의 모델이 항상 최상 모델인 것은 아니다.
    # 이 옵션 자체가 학습을 조기에 중단하지는 않는다.
    load_best_model_at_end=True,

    # 최상 모델을 선택할 기준: 검증 Macro-F1
    # compute_metrics가 "macro_f1"이라는 key를 반환해야 한다.
    metric_for_best_model="macro_f1",

    # Macro-F1은 값이 높을수록 좋은 지표다.
    greater_is_better=True,

    # 학습의 무작위 동작에 사용할 seed
    # 재현성을 돕지만, 이것만으로 모든 환경에서 동일 결과를 보장하지는 않는다.
    seed=SEED,

    # W&B 같은 외부 실험 추적 도구로 결과를 전송하지 않는다.
    # 학습 로그와 평가 자체를 끄는 설정은 아니다.
    report_to="none",
)


# ============================================================
# 2. Trainer 구성
# ============================================================
# 모델·데이터·배치 처리·평가 함수를 하나로 연결한다.
# Trainer를 만드는 것만으로 학습이 시작되지는 않는다.

trainer = Trainer(
    # 실제로 학습할 Sequence Classification 모델
    model=model,

    # 위에서 만든 학습·평가·저장 설정
    args=training_args,

    # 파라미터 업데이트에 사용할 학습 데이터
    # 이미 Tokenizer로 변환된 데이터셋이다.
    train_dataset=tokenized_dataset["train"],

    # 학습 중 성능 확인과 best model 선택에 사용할 검증 데이터
    # 최종 평가용 test와 역할을 구분한다.
    eval_dataset=tokenized_dataset["validation"],

    # 여러 샘플을 Tensor 배치로 묶는 객체
    # 앞에서 만든 DataCollatorWithPadding으로 동적 패딩을 수행한다.
    data_collator=data_collator,

    # 평가 logits와 정답으로 Accuracy, Macro-F1 등을 계산하는 함수
    compute_metrics=compute_metrics,

    # 이 모델에 사용하는 Tokenizer를 Trainer에 연결한다.
    # 이 인자를 넣는 것만으로 원본 데이터 전체가 자동 토큰화되지는 않는다.
    processing_class=tokenizer,
)

# train_result에는 학습 시간, step, 학습 loss 등의 요약이 담긴다.
train_result = trainer.train()
```

## 🧩 어려웠던 점
### 1. Validation과 test의 역할 구분
둘 다 모델 파라미터를 직접 업데이트하지 않지만, validation은 모델 선택에 사용된다. Test까지 반복해서 보며 설정을 수정하면 최종 평가의 독립성이 약해진다.
→ Validation은 선택용, Test는 선택 후 평가용으로 구분한다.
### 2. Validation와 Data Collator의 역할 구분
둘 다 입력 처리에 관여해 역할이 비슷하게 느껴질 수 있다.
→ Tokenizer는 문장을 숫자로 바꾸고, Collator는 여러 샘플을 길이가 맞는 배치로 묶는다.
### 3. Labels·Logits·Loss 구분
Labels는 정답, logits는 예측 점수, loss는 두 값의 차이를 학습 목적에 맞게 수치화한 값이다
→ 정답 → lables/예측 점수 → logits/학습기준 → loss로 연결한다. 
4. Softmax는 언제 사용하는지
확률을 확인할 때는 softmax가 필요하지만, 클래스 선택에는 logits의 argmax만으로 충분하다.
CrossEntropyLoss에도 softmax 이전 logits를 사용한다.
→ 확률 해석과 loss 계산을 구분한다. 
5. Accuracy가 높아도 모델이 부족할 수 있다는 점
다수 클래스만 맞혀도 전체 정확도가 높게 나올 수 있다.
→ Macro-F1 · 클래스별 Recall · 혼동 행렬을 함께 확인한다. 
### 6. Best model과 final model의 차이
마지막 학습 상태가 가장 좋은 모델이라고 생각하기 쉽다.
→ Best는 검증 기준으로 선택된 모델, final은 실제 사용을 위해 저장한 모델 묶음이다.
### 7. 코드의 라벨 매핑을 그대로 복사하면 안디는 점
7-6강 일부 예제의 negative/positive는 감성 분류용이다. YNAT 뉴스 분류에 적용하면 클래스 수와 의미가 맞지 않는다.
→ 라벨 목록은 데이터셋에서 읽고, 데이터**·**모델·평가에서 동일한 매핑을 유지한다.
### 8. Confidence가 높은 오류의 해석
높은 점수를 받았다고 반드시 정답인 것은 아니다. 잘못된 단서에 의존하거나 데이터 분포가 달라졌을 수 있다.
→ Confidence는 검토 우선순위를 정하는 단서로 사용하고, 실제 원문과 정답기준으로 원인을 확인한다.
