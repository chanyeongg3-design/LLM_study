# ❓ 왜 필요한가?
딥러닝 모델을 직접 구현하고 학습시키려면 **shape, dtype, device**를 정확하게 맞추는 것이 기본입니다. 또한 퍼셉트론 → MLP → `nn.Linear` → flatten → `nn.Module`로 이어지는 구조를 이해해야 나중에 학습 루프와 실제 모델을 만들 때 오류 원인을 스스로 찾을 수 있습니다.
# 🧠 핵심 개념
## 1. Device
- `cpu`: CPU 메모리에 Tensor가 있음
- `cuda` / `cuda:0`: NVIDIA GPU 메모리에 Tensor가 있음
- GPU 사용 가능 여부: `torch.cuda.is_available()`
- 장치 결정: `torch.device("cuda" if torch.cuda.is_available() else "cpu")`
- Tensor 이동: `x = x.to(device)`
- 모델 이동: `model = model.to(device)`
**핵심:** `model`, `inputs`, `labels`는 학습 시 같은 device에 있어야 합니다.
## 2. 퍼셉트론
퍼셉트론은 입력에 가중치를 곱하고 합한 뒤 편향을 더해 하나의 점수를 만듭니다.
`z = x1*w1 + x2*w2 + ... + xn*wn + b`
- `x`: 입력 feature
- `w`: 가중치
- `b`: 편향
- `z`: 점수(logit)
2차원에서는 결정 경계가
`w1*x1 + w2*x2 + b = 0`
이라는 **직선**이 됩니다.
## 3. 선형 결정 경계의 한계
퍼셉트론 하나는 선형 결정 경계만 만들 수 있습니다. XOR처럼 하나의 직선으로 분리할 수 없는 데이터에는 한계가 있습니다.
## 4. MLP
MLP는 여러 퍼셉트론을 층으로 쌓은 구조입니다.
`입력 → 은닉층 → 출력층 → logits`
예:
`X: (4, 3) → Linear(3, 5): (4, 5) → ReLU: (4, 5) → Linear(5, 2): (4, 2)`
- batch size는 유지됩니다.
- 주로 feature 차원이 바뀝니다.
- `hidden size`는 은닉층의 feature 수입니다.
- `depth`는 쌓인 학습 가능한 층의 깊이를 설명할 때 사용합니다.
- `width`는 은닉층의 크기를 말할 때 사용합니다.
## 5. `nn.Linear`
`nn.Linear(in_features, out_features)`는 입력의 마지막 차원을 `out_features`로 변환합니다.
`input shape: (batch_size, in_features)`
`output shape: (batch_size, out_features)`
PyTorch 내부 parameter:
- `weight.shape = (out_features, in_features)`
- `bias.shape = (out_features,)`
계산은 다음처럼 이해하면 됩니다.
`output = input @ weight.T + bias`
Parameter 수:
`in_features * out_features + out_features`
예: `Linear(3, 5)` → `15 + 5 = 20`
## 6. 이미지와 Flatten
이미지 batch는 보통 `(batch_size, channels, height, width)`입니다.
MLP는 `(batch_size, features)` 형태를 주로 기대하므로 이미지의 `channels * height * width`를 하나의 feature 차원으로 펼칩니다.
예:
- `(16, 1, 28, 28)` → `(16, 784)`
- `(N, 3, 32, 32)` → `(N, 3072)`
권장:
- `torch.flatten(x, start_dim=1)`
- `nn.Flatten()`
**중요:** batch 차원 `0`은 유지합니다.
## 7. `nn.Module`, `**init**`, `forward`
직접 모델을 만들 때는 보통 `nn.Module`을 상속합니다.
- `**init**`: 필요한 layer를 준비
- `forward`: 입력이 layer를 통과하는 순서 정의
예시 구조:
`flatten → fc1 → relu → fc2`
`model(images)`를 호출하면 내부적으로 `forward(images)`가 실행됩니다.
# 💻 직접 작성한 코드
```Python
# 라이브러리와 device 설정
# PyTorch와 신경망 관련 기능을 불러옴
import torch
import torch.nn as nn

# 현재 CUDA(GPU)를 사용할 수 있는지 확인 후, 가능하면 GPU 아니면 CPU를 사 
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

# PyTorch의 nn.Module를 상속받아 신경망 모델을 만듬
# 간단한 MLP(다층 퍼셉트론) 모델 정의
class SimpleMLP(nn.Module):

		# 모델의 층들을 정의하는 부분 
    def __init__(
		    self,
		    input_dim=1 * 28 * 28, # 입력 이미지 크기: 1 * 28 * 28 = 784
		    hidden_dim=128, # 은닉층 뉴련 수
		    num_classes=10 # 분류할 클래스 수
		):
        super().__init__() # nn.Module의 기본 기능 초기
        
        #[batch, 1, 28, 28] 이미지를 [batch, 784] 형태로 펼침 
        self.flatten = nn.Flatten()
        
        # 첫 번째 완전연결층
        #784개 입력 -> hidden_dim개 뉴련
        self.fc1 = nn.Linear(input_dim, hidden_dim) # (784, 128)
        
        #활성화 함수
        # 음수는 0으로 변경 
        self.relu = nn.ReLU()
        
        #출력층
        # hidden_dim -> 10개 클래스 
        self.fc2 = nn.Linear(hidden_dim, num_classes) #(128, 10)
		# 실제 데이터가 모델을 통과하는 과정 
    def forward(self, x):
			  
        x = self.flatten(x) # 이미지 펼치기
        x = self.fc1(x) # 첫 번째 Linear  층 통과
        x = self.relu(x) # ReLU 활성수 함수 적용
	      
	      logits = self.fc2(x) # 최종 10개 클래스 점수 출력
        return logits
# 은닉층 뉴런 128개, 분류 클래스 10개를 가진 모델을 device(CPU/GPU)로 이동
model = SimpleMLP(hidden_dim=128, num_classes=10).to(device)
# 랜덤 이미지 8장 생성, 형태: [이미지 개수, 채널, 높이, 너비]
images = torch.randn(8, 1, 28, 28).to(device)
# 이미지를 모델에 입력하고, 모델의 최종 출력값을 logits에 저장 
logits = model(images)

print("device:", device) # device 출력
print("images:", images.shape, images.device) # 이미지의 shape과 device 출력
print("logits:", logits.shape, logits.device) # logits의 shape과 device 출력
print("params:", sum(p.numel() for p in model.parameters())) # 모델 전체 학습 파라미터 개수 계산 
```

# 🤔 내가 헷갈렸던 부분
## `nn.Linear(4, 8)`에서 4와 8은 무엇인가?
4는 **batch size가 아니라 입력 feature 수**입니다. 8은 출력 feature 수, 즉 해당 층의 hidden size가 될 수 있습니다.
## `weight`가 왜 `(8, 4)`인가?
PyTorch는 `weight`를 `(out_features, in_features)`로 저장하기 때문입니다. 그래서 계산할 때 `weight.T`를 사용해 `input @ weight.T + bias` 형태가 됩니다.
## 왜 `flatten`에서 batch 차원을 유지해야 하는가?
샘플 여러 개를 각각 독립적으로 처리해야 하기 때문입니다. `(16, 1, 28, 28)` 전체를 하나로 펼치면 `(12544,)`가 되어 샘플 구분이 사라집니다.
## GPU를 켰는데 왜 Tensor는 CPU인가?
GPU 런타임을 켠 것과 Tensor가 GPU에 있는 것은 별개입니다. Tensor와 모델을 명시적으로 `.to(device)`로 이동해야 합니다.
# 💡 내가 이해한 방식
**퍼셉트론은 점수 계산기 → MLP는 점수 계산기를 여러 층으로 쌓은 것 →** **`nn.Linear`** **는 한 층의 실제 계산 → 이미지라면 먼저 flatten → 마지막에는 class별 logits가 나온다.**
그리고 모든 단계에서 `shape / dtype / device`를 확인하면 대부분의 초반 오류를 빠르게 찾을 수 있습니다.
# 🛠 디버깅 핵심
오류가 나면 다음 순서로 확인합니다.
1. `shape`
1. `dtype`
1. `device`
1. 모델이 기대하는 입력 차원
1. 예측값과 정답값의 shape
1. `CrossEntropyLoss`의 target dtype
1. broadcasting으로 shape가 의도치 않게 커졌는지
대표적인 오류:
- `Linear` 입력 feature 수 불일치
- `CrossEntropyLoss` target이 `float`인 경우 → `long` 필요
- model은 GPU인데 Tensor는 CPU인 경우 → device mismatch
- `(4, 1)`과 `(4,)` 연산으로 `(4, 4)` broadcasting이 생기는 경우
# 📝 오늘의 한 줄 정리
**딥러닝의 기본은** **`Tensor의 shape·dtype·device`** **를 맞추는 것이고, 퍼셉트론 → MLP →** **`nn.Linear`**  **→ flatten →** **`forward`**  **흐름을 이해하면 모델 구조와 오류를 스스로 읽을 수 있다.**
## 복습용 핵심 공식
```Plain Text
퍼셉트론:
z = x·w + b

Linear:
y = x @ weight.T + bias

Linear parameter:
in_features * out_features + out_features

이미지 flatten:
features = channels * height * width

MLP shape:
(batch, input_dim)
→ (batch, hidden_dim)
→ (batch, num_classes)

분류 target:
CrossEntropyLoss → class index, torch.long
```
